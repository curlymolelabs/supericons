Supericons Search v2

One fast search system, shared everywhere

Search v2 is bigger than the npm beta. The goal is one deterministic search engine for local MCP, hosted MCP on Railway, the website, and recommendations.

The same query should produce the same sensible results everywhere, quickly, without paying an AI provider for every search.

The practical roadmap

Protection work is a release requirement. The product payoff comes from bringing the proven engine to Railway, recommendations, and the website.

Finish beta.1 release hardening

Complete upstream licenses, repair the probe inventory, and close the post-approval rollback gap. Preserve staged-only minification, private canaries, and package-boundary checks.

Run the npm beta evidence window

Gather 200 organic attempts and three complete green days. Owner and agent use may count when correctly labelled. Scripted test suites do not count.

Remeasure hosted search on Supabase Micro

Measure only after disk and service health are green. Separate database capacity problems from query, network, and recommendation design problems.

Build and deploy the Railway hosted v2 route

Make the hosted entry use the built-in index for eligible searches. Verify result equality, Material support, cold and warm speed, memory, concurrency, fallbacks, and rollback.

Finish recommendations

Measure the shared recommendation pipeline using the corrected workload. Ship the hosted design if it passes. If it does not, stop repeating the same tuning loop and evaluate the local-index path.

Bring shared v2 behavior to the website

Run a separate, default-off web beta with the same query rules and ranking policy. Compare quality, speed, fallback behavior, and payload size before changing the public default.

Operate the reviewed learning loop

Detect ranking drift, repeated weak searches, new-icon collisions, and capability gaps. Prepare generic data fixes for review. Keep live searches deterministic and free from per-request model costs.

The one-sentence takeaway

Prove the built-in deterministic engine locally, bring it to the Railway route used by most MCP users, finish recommendations, then give the website the same search behavior. Add semantic models only if measured user failures justify their cost and unpredictability.
