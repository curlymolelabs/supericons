Production architecture audit

Web, local npm, and hosted MCP enter separately, but they are not recorded separately.

The entry points are different. The shared search services are also reasonable. The failure is in the logging boundary: Web traffic is relabelled as Hosted MCP, and the current stable local npm search can finish without any top-level search record.

Live website and database checked: 23 Jul 2026, 10:52 PM SGT Live MCP server: 0.4.22 Search mode reported by the live server: hosted primary

Audit verdict

The dashboard is following its rules. The events reaching it have the wrong roles.

Changing the dashboard labels alone cannot fix this. The website route and the local npm package must each create one final top-level event with the correct channel. Internal searches and translation retries must stay as supporting detail.

!

Web

Not trustworthy

Live website requests are currently stamped as Hosted MCP. The displayed Web count is not the number of website searches.

Local npm

Missing on stable

Version 0.4.22 searches locally, then the database function suppresses the final search event because it is not a beta cohort.

Hosted MCP

Best separated path

The hosted MCP tool writes one final event to the main request ledger. Its lower-level hosted searches are kept as diagnostics.

Architecture failures

Six breaks that must be fixed at the source

1

Web identity is discarded

The browser sends source=web, but the Railway public route does not keep it when it builds the search context.

2

Web has no final event

The route logs internal Supabase attempts but never writes one record for the final result returned to the website.

3

Retries look like separate outcomes

A translated retry can succeed after the original query returns zero. The current audit table stores both attempts but does not store the final combined outcome.

4

Stable local npm search is suppressed

The package records beta local-first searches, but the database function returns early for a stable search_icons event without a beta label.

5

Tests can look organic

Public-route test searches lack a dependable test label, so the dashboard switch cannot always separate tests from real use.

6

Old rollups preserve the wrong roles

Completed-day rollups include only rows already classified as top-level searches. Mislabelled Web rows are left out before the UI sees them.

Required target

One final event per entry point, with diagnostics kept separate

This preserves shared search infrastructure without mixing the three channels.

Website
One final event: channel=web
→
Web Search history and Web exports
Local npm
One final event: channel=local_mcp
→
Local MCP Search history and Request log
Hosted MCP
One final event: channel=hosted_mcp
→
Hosted MCP Search history and Request log
Shared search work
Attempts, translations, fallbacks, and timing
→
Diagnostics only, linked to the final event
  • Every completed search creates exactly one top-level event.
  • The entry point decides the channel. Shared services cannot replace it.
  • The final event stores the original query, final outcome, and final result count.
  • Each internal attempt stores a parent request ID and attempt number.
  • The main table counts final events only. The Audit bundle keeps both final events and diagnostics.
  • A daily check fails when Web traffic is stamped MCP, a stable local search has no final event, or a successful retry is presented as Zero.
