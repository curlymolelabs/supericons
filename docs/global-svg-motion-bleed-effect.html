Global SVG Motion Bleed

An accidental interaction pattern discovered during premium animated icon testing. The icon's motion leaked past the preview surface and made the whole page react like the icon itself. It is too disruptive for the default customize flow, but strong enough to keep as a future motion concept.

This demo separates three layers of the same idea: icon-only animation, intentional surface animation, and the accidental full-page bleed.

Capture Notes

Why it happened

The premium preview builder rewrote icon-targeted CSS selectors to :root. Once the SVG was mounted inline in the page, :root referred to the document root instead of an isolated icon container. 

.si-icon-cell:hover .mnv3on svg {
  animation: qascmc 0.5s cubic-bezier(0.22, 1, 0.36, 1) forwards;
}

becomes

:root {
  animation: qascmc 0.5s cubic-bezier(0.22, 1, 0.36, 1) forwards;
}
Keep the concept, not the side effect. If reused, bind the motion to a dedicated wrapper such as .motion-surface.is-animated rather than the document root.
Good Uses
  • Security alert pulses for threat-state transitions
  • Hero demos for premium animation collections
  • Short cinematic transitions between locked and unlocked modes
  • High-intent confirmation feedback on protected actions
Guardrails
  • Never ship it as a hidden side effect of inline SVG rewriting
  • Respect reduced-motion preferences
  • Use explicit triggers and brief durations
  • Prefer a scoped wrapper over the document root
