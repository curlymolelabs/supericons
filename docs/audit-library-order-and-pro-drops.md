# Audit: Library Order And Pro Drops

Date: 2026-04-06

## Scope

This audit covers two launch-near issues:

1. Reordering the icon libraries so `MingCute` and `Simple Icons` are prioritized near the top, while `Material Symbols` moves to the bottom.
2. Finalizing premium collection access for `Pro` without a credit system.

The goal is to reduce product ambiguity and remove internal contradictions before implementation.

## Executive Summary

Two different problems are showing up:

- Library ordering is currently incidental. It follows load/build order rather than an explicit product decision.
- Premium collection access is currently inconsistent across surfaces:
  - the web app still behaves like a credit-claim product
  - the MCP already behaves like `Pro = all premium access`

That means the codebase is already split between two monetization models.

The cleanest resolution is:

- make library order explicit in code
- replace the credit-based Pro story with a simpler drop/access model:
  - `Pro` unlocks all released premium collections while the subscription is active
  - new premium collection drops are automatically included for active Pro subscribers
  - permanent ownership remains a separate benefit of `Single Pack` and `Launch Bundle`

This aligns with the MCP, removes the credit state machine, and gives the product a clearer story.

## Audit Findings

### 1. Library order is not product-owned yet

Current behavior:

- `main.js` renders `state.libraries` directly in `renderLibraries()`
- `state.libraries` comes from `public/icon-index.json`
- `public/icon-index.json` is generated by `scripts/build-icons.js`
- the generated `libraries` array is built from `Object.entries(outlineCounts)` / `Object.entries(solidCounts)`

Implication:

- The order users see is effectively inherited from loader/build order, not from an explicit UX priority.
- That makes it fragile and difficult to reason about.

Relevant code:

- `main.js`
  - `libraryMeta`
  - `renderLibraries()`
  - assignment of `state.libraries = data.libraries`
- `scripts/build-icons.js`
  - final `outlineOutput.libraries`
  - final `solidOutput.libraries`

### 2. The current Pro pack model is internally inconsistent

Current web app behavior:

- `auth.js` still maintains a `creditBalance`
- `auth.js` reads from `si_credits`
- `store.js` shows a sidebar credit badge
- `store.js` pack cards show:
  - `Claim (X left)` when Pro + credits + not purchased
- `store.js` still calls Supabase Edge Function `redeem-credit`
- pricing copy still says:
  - `1 pack credit per billing cycle`
  - `3 bonus packs upfront (annual)`
  - `claimed packs are yours forever`

Current MCP behavior:

- `mcp/index.js` already treats `authState.isPro` as full premium access
- `hasLibraryAccess()` returns `true` for all premium libraries if `isPro`
- `getAccessibleIcons()` returns all premium icons for Pro

Implication:

- The product is already running two different Pro models:
  - web app: drip + claim + credits
  - MCP: active Pro unlocks all premium

This is the main product inconsistency that needs to be resolved.

### 3. The credit model adds complexity without clear upside

The current credit model requires:

- `si_credits` bookkeeping
- balance fetches in auth
- credit badge rendering
- claim CTA logic
- a separate redemption flow
- pricing and legal copy that explain a stateful credit mechanic
- edge-function dependency for redeeming

Observed downside:

- more UI states
- more user confusion
- harder copy
- harder entitlement reasoning
- inconsistency with MCP and Pro access expectations

### 4. A drop model without credits is much simpler and better aligned

A simpler Pro rule would be:

- `Pro` subscribers get access to all currently released premium collections while subscription is active
- future collection drops are automatically included
- no credit balance
- no claiming
- no manual unlock flow

Permanent ownership stays with:

- `Single Pack`
- `Launch Bundle`

This has several benefits:

- matches current MCP behavior
- removes claim friction
- reduces entitlement state
- simplifies copy across pricing, pack catalog, auth, and terms
- makes “premium collection drops for Pro” easy to explain

### 5. Existing purchases still matter

Even if Pro becomes all-access while active, permanent ownership still matters for:

- users who buy a single pack
- users who buy the Launch Bundle
- users who previously claimed packs through the old credit flow

So the new model should not delete historical purchase semantics.

Recommended transition rule:

- keep `si_purchases` as the permanent ownership source of truth
- treat prior credit-claimed packs as already purchased/permanent
- stop issuing and redeeming new credits
- hide credit balances and claim UI

### 6. The likely product fit is clearer than the current messaging

Recommended product framing:

- `Pro` = active subscription access to all premium collections + future drops
- `Single Pack` = permanent ownership of one collection
- `Launch Bundle` = permanent ownership of all launch collections

That gives each offer a distinct meaning:

- subscribe for ongoing access
- buy for permanent ownership

That is easier to understand than:

- subscribe, earn credits, choose claims, keep some forever, also get MCP all-access

## Risks

### Library order risks

- If only the runtime order changes, build output may still be inconsistent elsewhere.
- If only the build order changes, runtime-added or future libraries may still drift.

Best practice:

- enforce order at runtime for the actual user-visible sidebar
- optionally mirror the same order in build output for consistency

### Pro-drop migration risks

- copy, pricing, pack cards, auth badge, legal text, and MCP messaging must all move together
- otherwise the product will remain contradictory

### Historical-credit risks

- removing credit code too aggressively could break historical user expectations or edge cases
- safer approach:
  - stop using credits in UI and active flows first
  - retain historical records for migration safety

## Recommendation

### Library order

Adopt an explicit priority order and enforce it in the sidebar.

Recommended order:

1. `mingcute`
2. `simpleicons`
3. `lucide`
4. `tabler`
5. `phosphor`
6. `heroicons`
7. `bootstrap`
8. `iconoir`
9. `ionicons`
10. `material`

Reasoning:

- `MingCute` and `Simple Icons` are being intentionally promoted
- `Material Symbols` moves to the bottom as requested
- everything else keeps a stable middle order

### Premium model

Replace the credit system with this final rule:

- `Pro` subscribers get access to all released premium collections while active
- every new premium collection drop is automatically included for active Pro subscribers
- `Single Pack` and `Launch Bundle` remain permanent ownership options
- previous claimed packs remain in permanent ownership history

This is the cleanest model in both product and code terms.

## Conclusion

The right next move is not more patching of the old credit model.

It is:

- make library order explicit
- retire the credit-based Pro story
- align the app, pricing, MCP, and entitlement language around one rule:
  - active Pro = included premium access
  - purchases = permanent ownership
