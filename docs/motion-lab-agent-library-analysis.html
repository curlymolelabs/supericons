Part 1

Architecture Audit Summary

The Motion Lab product currently operates with two separate preset systems that have never been reconciled.

Interface File Preset count Origin
Browser UI store.js 80 presets Built first, human-tested
MCP tools lib/motion-lab-workflow.js 12 presets Added later, separately authored

The 12-preset MCP registry was not derived from the 80-preset browser system. It was written as a new file in a single commit (0c8f3e0), never reconciled with the source. It is not a curated subset. It is an architectural accident.

The Two Decisions

Decision 1 (cleanup): Remove the 12 orphaned MCP presets. Import from the authoritative browser source. This is a pure upgrade. No regression.

Decision 2 (build): Build a semantic metadata layer on top of the 80 correct presets, making them genuinely useful to agents - not just queryable by name.

The Correct Sequence

Step 1
Fix the registry split
One canonical preset source. Both browser UI and MCP server import from it.
Step 2
Expose all 80 via MCP
list_motion_presets() returns all 80, grouped by category.
Step 3
Build the agent metadata layer
Emotional tone, context guidance, intensity guidance, avoid-for. 80 records.
Step 4
Enrich MCP output
Tool returns structured metadata per preset, not bare names.
Part 2

Can an Agent Match a Human?

When a human opens Motion Lab in the browser, they have capabilities that seem impossible to replicate for an agent. Let's examine each one honestly.

Human in Browser
👁 Visual preview: see the animation playing on an icon in real time
🧠 Emotional intuition: immediate gut-feel about fit
🔀 Side-by-side exploration: compare bounce vs pop in seconds
✨ Serendipitous discovery: stumble onto something better
🎚 Adjustment loops: nudge intensity and immediately see the change
Agent with Library
📋 visual_character field encodes what the motion looks like in plain text
🏷 emotional_tone array maps the gut-feel to structured tags
🔍 recommended_contexts replaces browse-and-compare with filtering
⚠️ avoid_for replaces intuition with explicit constraint enforcement
📐 context_intensity_guidance encodes calibration as data

Most of what a human does visually can be encoded as semantic metadata. The key insight is that humans are not doing magic when they browse Motion Lab - they are applying taste, context knowledge, and pattern recognition. All three can be encoded.

The One Honest Gap

The library cannot fully replace taste-based discovery. Some of the best animation choices are found by accident - by trying something unexpected and noticing it works. The library encodes known-good patterns. It is excellent at avoiding bad choices and making correct choices. It is less capable of making a surprising, inspired choice that breaks the pattern in a way that feels right.

This gap closes over time as the library accumulates pairing_notes and unexpected_use_cases from real usage.

Verdict

With a well-built agent library, agents can match human quality for systematic, context-driven use cases and exceed human quality for consistency, constraint enforcement, and scale. The gap that remains is aesthetic serendipity - which is the smallest part of the job.

Part 3

Where Agents Exceed Humans

1. Consistency at scale

A human building a dashboard with 30 icons makes 30 individual aesthetic judgments. Fatigue sets in. By icon 20 they have drifted. An agent applies the same calibrated rules to all 30. Motion semantics stay consistent across the entire UI.

2. Constraint enforcement

Tell an agent "no high-intensity animations on destructive actions" and it will apply this rule perfectly across the whole product. A human forgets. The agent never forgets a constraint it has been given because the library's avoid_for field makes the constraint explicit and checkable at each decision point.

3. Context-aware pairing

Humans browse presets then think about icons. An agent reasons in both directions simultaneously: given this icon type and this product context, which presets are valid, which are optimal, and which are forbidden? The library gives it the vocabulary for this reasoning.

4. Speed and repeatability

Export 30 animated icons: a human clicks through 30 exports. An agent does it in one tool call loop. The library makes the decisions; the MCP tools do the exports.

5. Documented rationale

A human's choice of spin at 80% intensity is implicit intuition. An agent returns: "Selected sweep at 65% intensity, trigger: hover, for the settings icon. Rationale: enterprise fintech context requires restrained horizontal motion. Sweep signals precision and control. Bounce and pop were excluded due to high playfulness rating per avoid_for guidance."

Use case Human advantage Agent advantage
Single icon, exploratory High - visual discovery Adequate - filtered candidates
Single icon, defined context Adequate Equal or better
10+ icons, consistent tone Degrades with fatigue Strong - consistent ruleset
30+ icons, full UI system Significant drift risk Superior consistency
Constraint enforcement Best effort Perfect
Export speed Manual, sequential Programmatic, parallel
Part 4

Full Agent User Journey Map

Scenario

"Add hover animations to the icons in our premium fintech dashboard. The brand tone is professional, restrained, and refined. Not playful, not aggressive. These icons are in the primary navigation sidebar."

Phase 1
Context Capture and Constraint Formation

The agent reads the prompt and extracts a structured decision model before querying anything:

Product type: fintech dashboard Use location: primary navigation sidebar Trigger: hover (specified) Tone include: professional, restrained, refined Tone exclude: playful, aggressive, high-energy Icon function: navigation affordance (not status, not loading)

The agent does not yet know which presets exist. It is building the filter criteria first.

Phase 2
Library Consultation and Filtering

The agent calls the MCP tool:

list_motion_presets()

The library returns 80 presets with structured metadata. The agent filters immediately:

  • emotional_tone does not include "playful" or "energetic"
  • recommended_contexts includes "hover-affordance" or "navigation"
  • intensity_level is 1, 2, or 3 out of 5
  • Trigger compatible with hover

This narrows the field from 80 to approximately 8-12 candidate presets. The agent may also call get_motion_recipe() on any candidate to get a prose description of what the motion feels like.

Phase 3
Icon-to-Preset Mapping

The agent maps each icon to the most appropriate preset using best_for, ui_contexts, and avoid_for metadata:

Icon Context Selected preset Intensity Rationale
Home Primary anchor glow-soft 55% Subtle illumination, premium signal, low movement
Analytics Data, precision trace 70% Stroke trace reads as scanning, analytical
Portfolio Commerce, trust scale-soft 60% Gentle scale, warmth without aggression
Settings Config, control sweep 65% Horizontal precision sweep, deliberate feel
Notifications Alert, attention pulse 50% Low-intensity pulse, present but not alarming
Team Human, relational drift-up 55% Gentle upward drift, human warmth signal
Reports Static, reference shimmer 45% Subtle light pass, premium surface quality
Logout Destructive-adjacent fade-soft 40% Quiet exit: avoid_for guidance excluded bounce, sweep
Phase 4
Parameter Setting

For each selected preset, the agent sets parameters using library guidance - no guessing required:

  • Trigger: hover - specified in task, confirmed compatible
  • Intensity: Uses context_intensity_guidance - navigation-professional range 45-70%, lower half applied because "restrained" was specified
  • Duration: Uses timing_character and duration_range_ms - standard range 350-500ms for professional contexts

Note: drift and float presets are flagged by the metadata as needing longer durations (500-700ms) for naturalism. The agent respects this automatically.

Phase 5
Export via MCP

The agent calls export_motion_css() for each icon/preset pair:

export_motion_css( id: "home", library: "lucide", preset: "glow-soft", trigger: "hover", intensity: 55, duration_ms: 400 ) // Returns: production-ready CSS class

8 tool calls. 8 exports. A human would have clicked through 8 sequential exports in the browser UI.

Phase 6
Output Report to Developer

The agent delivers:

  1. The animated CSS for each icon, production-ready
  2. A rationale document explaining every selection decision
"Applied hover animations to 8 navigation icons. All presets selected from the professional/subtle tier (intensity 40-70%). Trace applied to Analytics to signal precision. Pulse applied to Notifications at 50% - above this threshold the library flags it as attention-seeking in sidebar contexts. Logout received fade-soft; sweep and bounce excluded by avoid_for guidance on destructive-adjacent actions. Duration range: 350-500ms for consistency."
Phase 7 (Optional)
Developer Follow-Up and Targeted Adjustment

Developer responds: "Increase the settings icon intensity. It feels too quiet."

The agent knows: current is sweep at 65%. Library ceiling for settings in professional contexts is 80% before it reads as aggressive. Agent updates to 75% and explains the ceiling.

No re-export from scratch. Targeted adjustment within a defined range. The library gave the agent the vocabulary and the boundary. The agent can communicate exactly where in that range it has moved.

Part 5

What the Library Must Contain

For the above journey to work, the motion preset metadata schema needs the following fields per preset. These are the fields that replace visual inspection with structured knowledge.

{ "preset": "sweep", "category": "Motion", "label": "Sweep", "aliases": ["scan", "trace-horizontal", "wipe"], "visual_character": "Icon strokes animate from left to right as a precision scan, creating a deliberate, controlled motion impression.", "emotional_tone": ["precise", "subtle", "professional", "premium"], "interaction_type": ["hover-response", "general"], "intensity_level": 2, "recommended_contexts": ["navigation", "settings", "analytics", "hover-affordance"], "avoid_for": ["playful-contexts", "onboarding-celebration", "success-confirmation"], "best_for": ["fintech", "enterprise", "SaaS-professional", "sidebar-navigation"], "context_intensity_guidance": { "navigation-professional": { "min": 55, "max": 80, "default": 65 }, "cta": { "min": 70, "max": 95, "default": 80 }, "subtle-affordance": { "min": 40, "max": 65, "default": 55 } }, "timing_character": "medium-precision", "duration_range_ms": [300, 500], "pairing_notes": "Works well on icons with horizontal lines. Less effective on circular or radial icons.", "output_notes": "CSS output uses stroke-dashoffset. Ensure icon has visible stroke paths." }

All 80 presets need this metadata. That is the curation work. The schema can be defined in a day. Populating 80 records with accurate, non-subjective, tested metadata is 1-2 weeks of editorial work.

Conclusion

The agent library is not a documentation project. It is a knowledge encoding project. The goal is to transfer the implicit visual knowledge a human has when browsing Motion Lab into structured metadata an agent can use to make equivalent decisions.

The browser UI remains the discovery surface for humans. The agent library becomes the decision surface for agents. These are not competing products. They are two interfaces to the same Motion Lab system, each optimized for a different kind of user.

The prerequisite is a single canonical preset registry. Build that first.
