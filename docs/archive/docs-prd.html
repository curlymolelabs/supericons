1. Problem Statement

Supericons launched with a documentation surface that covers MCP setup for three clients. The page is titled "Supericons Docs" but does not represent the full product. Pro users who pay for Motion Lab and Converter have no reference material. The current page creates a trust gap between payment and outcome.

The product is now broader than an icon browser:

  • 20,000+ free SVG icons across 10 libraries
  • Premium animated collections
  • MCP integration for coding agents (free and Pro tools)
  • Motion Lab (Pro): animation presets, CSS and SVG exports
  • Converter (Pro): PNG-to-SVG and SVG-to-PNG conversion

A docs section that only covers MCP setup does not serve this product.

2. Goals and Non-Goals

Goals

  • Build a docs section that accurately represents every part of Supericons that genuinely needs documentation.
  • Keep the top navigation intact. Introduce a dedicated docs left sidebar.
  • Ship once, cleanly. No placeholder pages. No "coming soon" in the sidebar.
  • Make every page verifiable against the shipped product before it goes live.
  • Position Supericons as a professional-grade developer tool with documentation quality to match.

Non-Goals

  • Do not document the free icon browse UI. It is self-explanatory.
  • Do not document the basic customize panel controls. They are labeled and intuitive.
  • Do not document pricing. The pricing page owns that.
  • Do not document legal content. Terms and Privacy pages own that.
  • Do not add speculative tools or features not yet shipped.

3. Intended Audience

Primary

Developers integrating Supericons through MCP. Comfortable with CLI tools, config files, and coding agents. Want correct commands and working examples.

Secondary

Pro subscribers using Motion Lab and Converter who need to understand parameters, output formats, and how to integrate exports into their projects.

Tertiary

Developers and designers evaluating Supericons for the first time. Need enough orientation to understand what the product does and whether it fits their stack.

4. Design Principles

Document complexity, not everything

Write docs for workflows where a user can waste 10 minutes making wrong choices without guidance. Skip docs for things the UI already explains clearly.

One source of truth

Each topic has one canonical page. No duplication of pricing, legal, or setup instructions across multiple unrelated pages.

Honest scope

Every sidebar item points to a finished page. No sidebar items that are promises rather than real content.

Launch once, launch cleanly

Because Supericons has not yet launched publicly, ship the complete first docs experience at once. Avoid a mid-state that requires a second redesign.

5. Resolved Decisions

5.1 Hero pill chips

Pills serve ambient awareness (what exists here). The sidebar serves active navigation (where to go). They are sequential, not competing. Keep pills, but refine copy from feature labels to value statements.

Approved pills for the docs home page:

20,000+ free icons Animated icons and CSS exports Works in Claude Code, Codex, Cursor

5.2 Interim title during build

Keep "Supericons Docs" as the title. Scope it with a subtitle: "MCP integration guides for Claude Code, Codex, and Cursor." This is accurate today. Once the full docs ship, remove the subtitle. No rewrite needed.

5.3 A, B, or C

Decision: Option C Patch the live page immediately (accurate title + subtitle). Build the full docs site in parallel. These are orthogonal concerns. Coupling them causes ongoing harm to users during the build window for no benefit.

Quickstart
/docs/quickstart
Free path (3 steps)

Step 1. Add the Supericons MCP server to your client. Choose your client for the exact command.

Step 2. Restart or reload your coding agent session so the server registers.

Step 3. Ask your agent to find an icon. Try: "Find me a settings icon from Lucide."

Premium path

To use premium collections, Motion Lab, or Converter through MCP, you need three things:

  • A Supericons account with Pro or a purchased collection
  • An API key from your Supericons dashboard
  • Your SUPERICONS_API_KEY added to your MCP client config

Free setup
# macOS / Linux
claude mcp add supericons -- npx -y supericons-mcp

# Windows
claude mcp add supericons -- cmd /c npx -y supericons-mcp

  "mcpServers": {

      "command": "npx",
      "args": ["-y", "supericons-mcp"]
    }
  }
}

Verify the server registered: type /mcp in Claude Code.

  "mcpServers": {
    "supericons": {
      "command": "npx",
      "args": ["-y", "supericons-mcp"],

        "SUPERICONS_API_KEY": "your-key-here"
      }
    }
  }
}

19
API Keys
/docs/access/api-keys
Core principle

An API key does not grant access by itself. It carries whatever entitlement your account already has.

What an API key does

Your Supericons API key identifies your account when you call MCP tools that require authentication. If your account has an active Pro subscription or a purchased collection, your API key carries that entitlement to the MCP server.

What an API key does not do
A key alone does not unlock premium features. If your account does not have Pro or a purchased collection, adding an API key to your MCP config will not change what tools are available to you. Access is determined by your account, not the key itself.

8. Launch Quality Gates

The docs section does not ship until all of the following are confirmed:

  • Every sidebar item points to a completed page
  • No placeholder text exists on any page
  • No "coming soon" appears anywhere in the sidebar or page content
  • All client setup commands are verified against official documentation sources
  • All tool names and parameters match the live MCP server
  • Motion Lab and Converter pages describe real, shipped product behavior
  • All internal links resolve to the correct pages
  • Pricing and entitlement language is consistent across all docs, the pricing page, and the API keys page
  • The verified-as-of timestamp appears on all three client setup guides

9. Execution Phases

Phase 1
Architecture lock

Finalize sidebar structure and URL map. Lock the 21-page set and the docs shell layout. Confirm what is in scope and what is intentionally excluded.

Phase 2
Core docs - orientation layer

Pages: Docs Home, What Is Supericons, Quickstart, API Keys, Pro and Collections, Troubleshooting. These must exist before any reference docs ship.

Phase 3
Client setup guides

Pages: Claude Code, Codex, Cursor. Highest-traffic pages. Near-complete copy already exists. Integrate into routed URL structure with verification timestamps.

Phase 4
MCP tools reference

Pages: MCP Tools Overview, Icon Tools, Motion Lab Tools, Converter Tools. Source material: live MCP server tool definitions.

Phase 5
Product guides - Pro depth

Pages: Motion Lab Guide, Presets, Triggers, Exports, Converter Guide, PNG to SVG, SVG to PNG, Settings Reference. These justify "Supericons Docs" as a title.

Phase 6
Consistency and verification pass

Align terminology across all 21 pages. Verify all setup steps against live official sources. Confirm all internal links. Add verified-as-of dates to client guides.

10. Writing Standards

Every page must answer, in order:

  1. What is this?
  2. Who is it for?
  3. What do they need first?
  4. How do they use it?
  5. What can go wrong?
  6. Where do they go next?
Non-negotiables Every command, file path, and tool parameter must be verified against the live product before the page ships. No jargon that a mid-level developer would not know without looking it up. Every page should be completable in one read sitting (under 4 minutes).
