# Supericons Docs Phase 1 Plan

**Date:** 10 April 2026  
**Status:** Approved working phase

---

## Phase Goal

Build the foundation of the full docs section now, while keeping the remaining pages ready for the next writing passes.

Phase 1 should deliver:
- the main docs shell
- the docs sidebar structure
- the first working docs page set
- the finalized MCP setup guides
- clearly labeled placeholder pages for sections whose content is not yet locked

This phase is for progressive build work. It is not the final public launch.

---

## What Phase 1 Includes

### 1. Full docs shell

Create the permanent docs structure inside the Supericons site:
- top navigation stays
- docs has its own left sidebar
- docs pages use one shared page template
- mobile navigation remains usable

### 2. First live docs pages

Phase 1 should include real content for the pages that are already strongest and most ready:
- Docs Home
- Quickstart
- Claude Code
- Codex
- Cursor

These pages create a real starting experience instead of a blank frame.

### 3. Placeholder pages for the remaining sections

The remaining docs pages should exist in the structure, but use clear temporary framing until their final copy is ready.

Each placeholder page should say:
- what this page will cover
- what to use right now
- where to go next

This keeps the architecture real without pretending unfinished pages are complete.

### 4. Compatibility with existing docs entry points

Current docs links and current client-guide entry points should continue to work while Phase 1 is in progress.

---

## Content Standard For Phase 1

### Finalized content to use now

Use the approved copy and tone already available for:
- Docs Home
- Quickstart
- Claude Code
- Codex
- Cursor

### Placeholder standard

Placeholders should feel intentional, not empty.

They should not say:
- coming soon
- under construction
- unfinished draft

They should say, in plain language:
- what this section will explain
- which live page already helps the user today

---

## Sidebar Structure For Phase 1

The full sidebar structure should appear now so the information architecture is visible from the start.

- Overview
- MCP Setup
- MCP Tools Reference
- Motion Lab
- Converter
- Access and API Keys
- Troubleshooting

Pages with finalized copy should open real content.
Pages without finalized copy should open structured placeholders.

---

## Build Order

### Step 1. Build the docs shell

Deliver the shared shell first:
- docs sidebar
- page header pattern
- content container
- page navigation pattern

### Step 2. Move the finalized MCP pages into the new shell

Add the first real pages:
- Docs Home
- Quickstart
- Claude Code
- Codex
- Cursor

### Step 3. Add placeholders for the remaining pages

Create the full docs map now so the structure is visible and testable.

### Step 4. Verify the foundation

Check:
- desktop layout
- mobile layout
- sidebar behavior
- links between docs pages
- compatibility with current docs entry points

---

## Phase 1 Success Standard

Phase 1 is complete when:
- the docs section has a real shell
- the sidebar reflects the full intended docs structure
- the finalized MCP setup content is live inside the new shell
- unfinished sections are represented by clear, useful placeholders
- the site remains stable and existing docs links still work

---

## What Happens Next

After Phase 1, the remaining docs sections can be filled progressively in this order:
- MCP tools reference
- Motion Lab pages
- Converter pages
- Access and troubleshooting refinements

That lets the docs section grow page by page without rebuilding the shell again.
