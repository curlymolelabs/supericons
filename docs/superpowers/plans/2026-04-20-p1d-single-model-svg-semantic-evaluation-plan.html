P1-D Single-Model SVG Semantic Evaluation Plan

Goal: Test whether one strong model can handle the first real semantic review pass for the SVG-ready purpose-chip icons.

Approach: Use the pilot files that already exist, make one balanced batch from the icons that already have SVG data, review that batch with one strong model, and record both timing and token estimates for the visible batch payload.

What This Covers

  • choosing a balanced SVG-ready test batch
  • reviewing the batch with one strong model
  • saving improved semantic records and review notes
  • recording elapsed time
  • estimating visible prompt and output tokens

What This Does Not Cover

  • the Material icons that still do not have SVG payloads in the pilot
  • automatic publishing into the live registry
  • reviewing all 150 icons in one pass

Main Steps

1. Freeze one balanced SVG-ready batch

  • pull from the current pilot files
  • keep only icons with real SVG payloads
  • include a mix of clearer and less-clear cases

2. Review the batch with one strong model

  • check what each icon shows
  • check whether the draft meaning fits the image
  • improve purpose, use-when, avoid-when, tags, and synonyms where needed
  • save confidence and review notes

3. Record time and token estimates

  • record start and finish time
  • estimate visible input tokens for the batch and instructions
  • estimate visible output tokens for the reviewed results
  • clearly label these as estimates, not hidden reasoning-token counts

Success Standard

This batch is successful if it gives us a fair answer to one question: is one strong model good enough right now to produce semantic tags that meet our current minimum quality bar without needing a split-model setup?
