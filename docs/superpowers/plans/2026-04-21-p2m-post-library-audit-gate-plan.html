Post-Library Audit Gate Plan

This step adds one shared audit check that runs after a whole icon library is marked complete. The point is to stop guessing. We want one clear answer about whether the library is fully counted, safely published, and ready to close.

What the audit must check

  • Does the final total match the official size of the library?
  • Does the public registry show the same number of approved records?
  • Did any private workflow fields leak into the records?
  • How many icons are approved, on hold, or still draft-level?
  • Is the library fully clean, or only complete with follow-up work still left?

What this step will produce

  • A reusable JSON audit report
  • A technical Markdown report
  • A simple HTML report for easy review
  • The first real audit run for Lucide

How we judge the result

  • If the totals do not match, that is a blocker.
  • If the public registry count does not match the approved count, that is a blocker.
  • If private workflow fields leaked into the records, that is a blocker.
  • If some icons are still on hold or still draft-level, that is not a blocker, but it must be called out clearly as follow-up work.

What success looks like

After this step, every finished library can close with the same audit standard. That means we can say whether a library is fully clean or only finished at the pipeline level, with no mixed messages.
