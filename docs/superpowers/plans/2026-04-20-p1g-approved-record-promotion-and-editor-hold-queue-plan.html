P1-G Approved Record Promotion And Editor Hold Queue Plan

This step turns the reviewed icon work into a real import-ready set, while keeping the harder icons in a smaller queue for later tightening.

Goal

Move the reviewed records that are good enough into the approved import file, keep the unresolved ones in a smaller editor queue, and make sure future pilot builds do not erase that progress.

Why this matters

The review work is now ahead of the import path. We already have reviewed records and a quality standard, but the approved file is still empty. This step closes that gap.

What will happen

  1. Create a small decision file that says which reviewed records are ready for import and which still need editor tightening.
  2. Generate a clean approved-record file that matches the registry rules.
  3. Generate a smaller editor hold queue for the records that are not ready yet.
  4. Change the pilot build so it keeps the approved file instead of resetting it to empty.
  5. Run checks so the approved and hold sets stay consistent.

Promotion rule for this slice

For this step, all reviewed records from batches 01 and 02 move into the approved path. Batch 03 keeps its current split between approved, hold, and draft records.

This keeps the clearer reviewed work moving without flattening the harder ambiguity cases.

Expected result

  • The purpose-chip pilot will have a real import-ready approved set.
  • The unresolved records will be isolated into a smaller editor queue.
  • Running the pilot build again will no longer wipe the approved set.
  • The next step will be a short editor pass on only the hold records.

Checks

  • npm run build:purpose-chip-approved-records
  • npm run verify:purpose-chip-approved-records
  • npm run build:purpose-chip-pilot
  • npm run verify:purpose-chip-pilot
  • npm run build
