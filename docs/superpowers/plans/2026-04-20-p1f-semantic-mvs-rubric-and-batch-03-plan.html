P1-F Implementation Plan

Define the minimum quality bar, then test it on a harder batch

This phase turns the quality bar into a real working rule. First we define what “good enough” means for a semantic icon record. Then we test that rule on a new batch of more ambiguous icons.

Why This Step Matters

  • we already have reviewed batches, but no firm approval rule
  • without a clear bar, approval decisions stay subjective
  • harder icons are a better test than obvious ones

What This Phase Will Do

  • write the semantic minimum standard
  • turn that standard into a simple rubric
  • choose a new batch of more borderline icons
  • review that batch against the rubric
  • record which icons would pass, hold, stay draft, or need rewrite

Main Steps

1. Freeze the approval rubric

Define the required gates for identity, visual read, purpose, use guidance, avoidance guidance, tags, lane fit, and confidence.

2. Build a harder batch 03

Choose 12 icons that are more ambiguous, more context-sensitive, or more likely to drift away from their seeded category.

3. Review the batch using the rubric

Render the icons into a contact sheet, review them one by one, and record both the semantic recommendation and the approval outcome.

4. Measure and verify

Record timing and visible token estimates, keep the files clean, and make sure the build still passes.

What Success Looks Like

  • the minimum quality bar is written down clearly
  • batch 03 exists and focuses on harder icons
  • reviewed outputs and notes exist for the batch
  • approval outcomes are explicit instead of implied
  • the build stays green
