Approved Semantic Import and Agent Test Plan

Main goal: move the 30 approved icon meaning records into the real registry output, let agents read that meaning through MCP, and then measure whether that extra meaning helps them choose better icons.

Main idea: keep the change small and safe. We are not rebuilding search from scratch. We are adding reviewed meaning data to the real output path, attaching it to tool results, and then testing if that extra meaning makes the answers better.

What This Step Adds

1. Real Registry Import

The 30 approved free icon records stop being pilot-only files and become part of the real public-safe registry output.

2. Agent-Readable Meaning

MCP search and icon lookup responses will include useful meaning fields like purpose, when to use the icon, and when not to use it.

3. Proof That It Helps

A small benchmark will compare search results before and after the semantic layer is available to see if agents can pick better icons.

Files That Will Change

  • data/si-registry/registry-manifest.json to register the approved records as a real free record group.
  • lib/si-registry/projections.js and scripts/build-si-registry-projections.mjs to publish a public-safe record file.
  • mcp/index.js plus a new helper so MCP can attach semantic meaning to icon tool results.
  • data/si-registry/benchmarks/agent-usefulness-fixtures.json and a new evaluation script to measure whether the extra meaning helps.
  • A new simple HTML report to show the outcome in plain language.

What Agents Will Be Able To Read

When an icon has approved meaning data, the tool result will be able to include fields like:

  • label
  • purpose
  • category
  • semantic_tags
  • synonyms
  • use_when
  • avoid_when
  • depicts
  • intent
  • domain
  • confidence

This is the part that matters for agents. The goal is not to make a prettier page. The goal is to let the agent read meaning directly.

How We Will Test It

We will use a small set of real prompts such as assistant reply, trusted protection, blocked action, and code search.

For each prompt, we will check:

  • what search returns first right now
  • whether the expected icon appears in the top results
  • how many of those top results now carry approved meaning data
  • whether the meaning data helps choose the right icon from the same candidate list

What Success Looks Like

  • The real public-safe registry output contains the old 6 public records plus the new 30 approved ones.
  • MCP can return icon meaning for those reviewed records.
  • We can show, with a repeatable benchmark, that the meaning layer helps agents make better icon choices.
  • The whole step stays public-safe and avoids internal workflow details.
