Registry Provider Branding Policy

This rule keeps the public registry clean. Supericons should be clearly shown as the provider of the registry, but that branding should live in the registry summary and docs, not inside every single icon record.

What goes at the top level

The registry summary can show who runs the registry. That is the right place for fields like the provider name, the short namespace, and the main website.

  • provider.name
  • provider.namespace
  • provider.homepage

What stays out of each icon record

Third-party icon records should stay focused on the icon itself. They should describe the icon meaning, when to use it, and which library it came from. They should not repeat Supericons branding on every item.

  • Do not add a Supericons homepage to every third-party icon record.
  • Do not add repeated provider fields to every third-party icon record.
  • Keep the source library honest, such as heroicons or lucide.

When the si: prefix is allowed

The si: prefix is allowed for icons that truly belong to Supericons. That is a source label, not an ad. It should not be copied onto icons that really came from another library.

Why this is the better pattern

  • It keeps public records smaller and easier for agents to read.
  • It keeps the original library source clear.
  • It avoids turning every icon record into a branding block.
  • It still leaves room for real Supericons-native icons later.
