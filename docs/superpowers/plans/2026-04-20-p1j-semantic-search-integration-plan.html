Semantic Search Integration Plan

The benchmark showed the core issue clearly: the reviewed icon meaning data exists, but search usually does not return those icons in the first place. So the next step is not more tagging. The next step is to let search use the reviewed meaning data to pull better candidates into the result list.

Main Idea

Keep the current search engine as the starting point. Then add one small layer that checks the approved meaning records and brings in matching icons when the normal search misses them.

This keeps the current search behavior, but gives the reviewed icons a real chance to appear for prompts like assistant reply, blocked action, and delete item.

What Will Change

  • Add a helper that scores the public-safe semantic records against a search query.
  • Merge those semantic matches into MCP search results when they are strong enough and not already present.
  • Update the benchmark so it compares plain search against semantic-augmented search.
  • Regenerate the usefulness report to see if candidate coverage improves.

What Will Not Change

  • The main search engine will stay in place.
  • This step will not widen semantic coverage to more icons yet.
  • This step will not change premium access or other MCP tools.
