Goal

Make Supericons MCP easy for any agent to use well

The main problem is not whether the server works. The main problem is whether an agent can quickly get to the right icon without having to do too much manual thinking, retrying, and cleanup.

Right now the MCP works, but it still asks too much from the agent. The agent often has to guess search words, retry with simpler words, and read raw SVG text when it should be reviewing clear recommendations.

What We Learned

The meaning data helped, but the experience still feels rough

The SI meaning data already proved useful in the benchmark. It improved the best first result from 1 out of 12 to 11 out of 12 when the retrieval layer used it properly.

So the meaning data is not the failure. The gap is that the current MCP still behaves too much like a raw search box and not enough like a recommendation assistant.

Core Question

Would a weaker agent still do well here?

If an agent is weaker than Kimi, would it still choose good icons without having to manually simplify the request into single-word searches?

That is the real test. A strong model can often recover from rough tools. A good MCP should not require that much recovery in the first place.

North Star

What the final experience should feel like

An agent should be able to handle a request like:

"Find the best MingCute icons for these 4 navigation buttons and show previews before implementation."

It should do that in one clean pass, without forcing the agent to break the job into brittle keyword fragments like home, add, notification, and user.

Design Rules

Fit how agents think

Agents think in jobs like "pick the best icon for Home", not in library token guessing.

Lower the thinking burden

The MCP should do more of the routine work, such as intent cleanup, synonym handling, and ranking.

Fail gracefully

Local MCP should not show raw hosted errors if local data can answer the request.

Preview before action

If the user asks to review first, the tool should return preview-friendly output instead of long raw SVG blocks.

Work for weak and strong agents

The tool should be easy for a weaker agent and simply faster for a stronger one.

Enhancement Plan

Main changes

  • Make local MCP search fall back safely instead of surfacing raw hosted errors.
  • Improve multi-word search so natural phrases do not collapse into zero results.
  • Add a new recommendation tool for design tasks, instead of relying only on raw search.
  • Return preview-friendly output so agents can show candidates clearly before implementation.
  • Benchmark the experience for weak, medium, and strong agent behavior.

New Tool Direction

Add a recommendation-first tool

The current MCP is good for exact lookup, but not yet great for "help me choose" tasks.

The plan is to add a tool such as recommend_icons that accepts a design task and a list of UI slots, then returns:

  • best match for each slot
  • good alternatives
  • a short reason for the choice
  • meaning fit notes
  • preview-ready SVG data

This would let agents solve the problem in one or two calls instead of many small search-and-retry steps.

Success Check

How we will know it worked

  • Agents no longer need to manually simplify requests into single-word searches.
  • Local MCP does not show raw hosted 502 errors when local data is available.
  • Agents can show clear candidate previews before implementation.
  • Weaker agents can still get suitable icon recommendations in a small number of tool calls.
  • The new benchmark shows better real task performance, not only better raw retrieval scores.

Recommended First Slice

Do this in one small vertical slice first

  1. Make local fallback safe by default.
  2. Add the new recommendation tool.
  3. Test it on the bottom navigation use case.
  4. Improve preview output for that flow.

That gives a visible before-and-after upgrade quickly, without redesigning every tool at once.
