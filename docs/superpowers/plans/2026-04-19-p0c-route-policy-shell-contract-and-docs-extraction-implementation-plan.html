P0-C Implementation Plan

Routes, shell ownership, and docs cleanup

This is the next build step after the product-facts work and the first browser QA pass. The goal is to make route behavior intentional, reduce risky cross-file coupling, and move the docs view into cleaner modules without changing how the product feels to the user.

Goal: keep launch work stable now, then prepare the app for the bigger SI Registry and semantic rollout later.

Main Roadmap We Are Following

P0-A

Done. Product facts were centralized and the packs heading bug was fixed.

P0-B

Done. Real browser QA was run and the biggest refactor risks were identified.

P0-C

This plan. Clean up route behavior, add a shared shell contract, and pull docs code out of store.js in a safe first slice.

P1 and after

Only after P0-C is green do we start SI Registry scaffolding and then the longer semantic rollout.

What This Phase Decides

  • Store routes that already support direct links should keep their ?view= URL after the page loads.
  • collection-detail stays non-shareable for now because it still depends on internal state instead of a public route model.
  • main.js stays the owner of shared shell DOM and shell layout rules.
  • store.js should ask for shell changes through a shared contract instead of editing shell elements directly.
  • Docs is the first safe cleanup slice because it already behaves like a separate route family.

Files This Plan Adds

  • lib/view-route-policy.js for all route rules in one place
  • lib/store-shell-contract.js for the shared shell API used by store views
  • lib/docs-guide-config.js for docs guide data now trapped inside store.js
  • lib/docs-site-render.js for docs page markup builders
  • scripts/verify-view-route-policy.mjs for route checks
  • scripts/verify-store-shell-contract.mjs for shell checks
  • scripts/verify-docs-site-render.mjs for docs rendering checks

Files this plan changes

  • package.json
  • main.js
  • store.js
  • docs-pages.js
  • scripts/verify-icon-grid-behavior.mjs if extra route ownership checks are needed

Implementation Steps

1. Put all route rules in one place

Create one route policy file that answers simple questions:

  • Should this view stay in the URL?
  • Does this view use the store shell?
  • Should this view suppress the side panel?
  • Should the header search be in icon mode or docs mode?

Verification script:

node scripts/verify-view-route-policy.mjs

2. Add a shared shell contract

Make main.js expose a small shared API for store views, such as:

  • set page title and small subtitle text
  • switch header search mode
  • hide or restore the side panel
  • reset the premium panel placeholder
  • scroll the main grid back to the top

This means store.js stops doing raw shell DOM setup during route switches.

Verification script:

node scripts/verify-store-shell-contract.mjs

3. Wire the route logic and shell contract together

Update switchView() and route restore logic in store.js to use the new route policy and the new shell contract. Keep the heading-protection checks green while doing this.

Main checks:

node scripts/verify-view-route-policy.mjs
node scripts/verify-store-shell-contract.mjs
npm run verify:icon-grid-behavior

4. Move docs guide data out of store.js

Extract the large docs guide configuration into lib/docs-guide-config.js. This is safe because it is mostly content and structure, not shared app state.

5. Move pure docs page rendering out of store.js

Create a docs rendering helper that builds sidebar, pagination, and page markup. Keep event wiring in store.js for now. This reduces risk because we are only moving pure rendering first.

Verification script:

node scripts/verify-docs-site-render.mjs

6. Run full checks and do a user QA checkpoint

node scripts/verify-view-route-policy.mjs
node scripts/verify-store-shell-contract.mjs
node scripts/verify-docs-site-render.mjs
npm run verify:icon-grid-behavior
npm run verify:search-query-fixtures
npm run build

User Test Checkpoint

When execution reaches the QA step, stop and ask the user to test these one by one:

  1. Open /?view=packs and confirm the heading is Premium Collections and the URL still shows ?view=packs.
  2. Open /?view=pricing and confirm the heading is Pricing and the URL still shows ?view=pricing.
  3. Open /?view=docs-mcp-tools#icon-tools-search and confirm both the page and the scroll target work.
  4. Use the docs search in the header and confirm a result opens the right docs page.
  5. Go back to All Icons and confirm the search box returns to icon mode.

The next big registry and semantic work should not begin until this checkpoint is green.

What Success Looks Like

  • Shareable store routes keep their URL after load.
  • Route rules live in one clear place.
  • main.js clearly owns the shell.
  • store.js stops grabbing shell DOM during route switching.
  • Docs content and pure docs page rendering move out of store.js.
  • The next cleanup and registry steps become safer and easier.
