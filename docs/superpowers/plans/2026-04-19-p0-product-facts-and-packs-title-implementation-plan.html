P0 Product Facts and Packs Title Plan

Goal: stop visible count/version drift, create one shared facts source, and fix the packs page heading bug safely.

Main idea: do the smallest high-value foundation work first.

  • make one shared facts file from the real data
  • use that facts file in the first top-surface places that currently drift
  • fix the packs heading bug with a testable helper instead of a risky rewrite

Files We Will Add

  • data/product-facts.json for shared counts and labels
  • scripts/build-product-facts.mjs to generate it
  • scripts/verify-product-facts.mjs to check it
  • lib/product-facts.js so the app can read the shared facts cleanly
  • docs/superpowers/plans/2026-04-19-product-facts-drift-inventory.md for the drift snapshot

Files We Will Change

  • package.json
  • main.js
  • store.js
  • docs-pages.js
  • lib/icon-grid-behavior.js
  • scripts/verify-icon-grid-behavior.mjs
  • mcp/index.js

Task 1: Inventory The Drift

  • make one doc that lists the important drifted strings first
  • mark each item as marketing copy, product truth, or technical metadata
  • mark where each item should read from in the future

Task 2: Build Shared Product Facts

  • write the verification script first so it fails when the facts file is missing or stale
  • build the facts file from the real free icon index, premium manifest, and MCP metadata
  • add build and verify scripts to package.json
  • run the build before the main app build

Task 3: Wire The First Consumers

  • use shared facts in the app’s top-surface count strings
  • use shared facts in MCP free-icon labels
  • stop MCP version drift by reading the package version directly

Task 4: Fix The Packs Title Bug

  • add a failing check first
  • move title resolution into a small helper
  • keep store views in charge of their own heading text
  • avoid a broad shell refactor in this step

Task 5: Verify Everything

  • node scripts/verify-product-facts.mjs
  • npm run verify:icon-grid-behavior
  • npm run verify:search-query-fixtures
  • npm run build

Why This Order

This order fixes what users can already see, gives the project one shared source for counts and tool numbers, and avoids jumping into the larger registry work before the app stops contradicting itself.
