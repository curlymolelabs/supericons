P1-C Implementation Plan

Run the first semantic pilot on the 3 purpose-chip sets

This phase uses the three icon groups already behind the purpose pill chip filter as the first semantic operations pilot. That gives us a clean test set of 150 icons: 50 for AI & Agents, 50 for Navigation & Wayfinding, and 50 for Status & Feedback.

The plan allows a lighter first-pass reviewer only for simple visual confirmation, while stronger review is reserved for difficult cases.

Why This Is a Good Pilot

  • the icons are already curated
  • the sets already matter to product thinking
  • the total size is manageable at 150 icons
  • we can test automation without opening the whole free icon catalog

Main Rule

This pilot should create draft candidates, visual-review inputs, and review queues. It should not automatically publish all generated results into the live public registry.

Model Choice For This Pilot

  • Use deterministic rules first to create a draft.
  • Use a lighter first-pass reviewer only when it adds value.
  • Only send hard or conflicting cases to stronger review later.

What This Phase Builds

  • a generated worklist for the 150 pilot icons
  • draft semantic records for each icon
  • visual-review inputs for each icon
  • a review queue based on confidence and ambiguity
  • an approved-record import file separate from raw candidates

Implementation Steps

1. Freeze the pilot worklist

Generate the list directly from the current purpose-chip seed so the pilot stays tied to the real product experiment.

2. Add lane defaults

Create one simple mapping file for the three lanes so each group has clear default category, domain, and intent rules.

3. Generate draft semantic records

Use names, ids, source libraries, and lane defaults to create a first semantic draft for each of the 150 icons.

4. Prepare visual-review inputs

Build a file that pairs each icon with its SVG and current draft meaning so visual review can happen in a structured way later.

5. Route records into review queues

Group draft records into lanes like high confidence, needs review, ambiguous, and stronger-review-needed, and make those queues explicit in a file.

6. Separate approved records from draft candidates

Approved records should have their own import file. Draft candidates should not be treated as live registry records.

7. Add checks

Verify the 150-icon count, the 50/50/50 split, and that approved imports are a clean subset of the pilot records.

What Success Looks Like

  • all 150 pilot icons have draft semantic records
  • all 150 pilot icons have visual-review inputs
  • review queues exist and are easy to inspect
  • approved imports are cleanly separated from drafts
  • the full build still passes
