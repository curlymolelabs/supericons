Supericons Product Requirements Document — May 2026

From Icon Search
to Visual Computation

A phased implementation plan to evolve Supericons from the world's most semantic icon search engine into the infrastructure layer for visual meaning — where humans, agents, and software all speak the same visual language.

● Current: semantic icon search + MCP
● Target: visual computation platform
● Horizon: 18–24 months
Part I

Executive Summary

Supericons operates at the intersection of three accelerating trends: AI agents building UIs at scale, the commoditization of visual generation, and the growing need for semantic precision in human-machine interfaces. This PRD defines the product and implementation path from the current state (icon search + MCP) to a visual computation platform — a new category of software infrastructure.

Part II

Where We Are Now

A candid assessment of what exists today, what works, and what gaps exist between the current product and the vision.

Strength
Semantic Search Engine
CJK-optimized, multilingual (12 languages), intent-based ranking, fuzzy matching. The moat is already here.
Strength
MCP Server
13 tools across free and Pro tiers. npm package (@supericons/mcp). Hosted HTTP transport on Railway. Claude Code, Codex, Cursor, Windsurf, OpenCode support.
Strength
Motion Lab + Converter
32 animation presets, CSS + animated SVG export. SVG↔PNG converter with quality controls. Pro-gated but full-featured.
Gap
No Runtime SDK
Icons are downloaded as files or via MCP. No npm package for using icons in apps at runtime. Developers stitch together their own solutions.
Gap
No Parametric System
Motion Lab applies animation presets, but icons cannot adapt their structure based on state. A "save" icon is always the same SVG, just with different CSS.
Gap
No AI Generation
No "describe what you need, get an icon" flow. Forge does not exist yet. AI agents using MCP still pick from the existing catalog — they cannot create.
Part III

Product Strategy

The core insight: SVG is code. It is structured, parseable, composable, and AI-readable. This means icons can evolve from static assets into dynamic, programmable visual primitives. The strategy is to build this capability layer by layer, each phase creating a defensible moat.

Evolution Path: Each Phase Compounds
Phase 1
Animated state icons as a product. Motion Lab is the foundation. Developers get one-line stateful icons. First wedge that proves value.
→
Phase 2
Parametric schema + Runtime SDK. Icons become functions of state/context. Web Components ship. Mental model shifts from "find" to "describe."
→
Phase 3

→
Phase 4

Primary Audience

2
Parametric System + Runtime SDK
Months 4–6 | Effort: 14–20 person-weeks
Outcome: A parametric icon schema standard (JSON-based), a runtime engine that interprets schemas (@supericons/runtime), and Web Component wrappers (<super-icon>). Developers write <super-icon intent="save" state="syncing" /> and get a correctly animated, accessible, themable icon. The mental model shifts from "which icon asset?" to "what am I trying to communicate?"

Months 7–12 | Effort: 18–26 person-weeks
Outcome: Supericons Forge — text-to-parametric-icon generation. Users (and AI agents) describe what they need in natural language, get back a PIS schema, preview it, tweak parameters, and export. A visual grammar engine that composes icons from primitives, enabling on-demand creation of icons that do not yet exist in any catalog.

Technical Architecture (Target State)

Part V

Architecture Decisions

Principle-level decisions that guide implementation. Each one is a deliberate trade-off.

AD-01
SVG is the universal intermediate representation. All icons, regardless of source (catalog, AI-generated, composed), resolve to optimized SVG before hitting any renderer. SVG is human-readable, AI-parseable, universally supported, and natively accessible. It is the "bytecode" of visual icons.
AD-02
CSS for animation, not JavaScript. The runtime uses CSS animations (keyframes, transitions) for icon motion. CSS animations run on the compositor thread, avoid main-thread jank, and automatically respect prefers-reduced-motion. JavaScript is used only for state management and path interpolation where CSS cannot reach (e.g., SVG path morphing).
AD-03
Web Components for framework portability, not as the only way. <super-icon> wraps the runtime in a custom element that works everywhere. But the low-level @supericons/runtime package has no DOM dependency — it works in Node, Deno, workers, and non-browser environments. Framework wrappers (React, Vue, Svelte) are thin adapters.
AD-04
PIS schema is the source of truth, not individual SVG files. The current catalog of 21K icons gets wrapped in PIS. Going forward, all new icons are authored as PIS schemas. This enables diffing, versioning, AI generation, composition, and multi-surface rendering from a single source.
AD-05
Free core, Pro features, Enterprise platform. The runtime, elements, states packages, and basic PIS schemas are free and open-source (MIT). Forge AI generation, advanced animation presets, private registry, and enterprise features are paid. This matches existing pattern (free icons / Pro Motion Lab). The registry marketplace is open: anyone can publish free schemas. Premium schemas are paid.
AD-06
MCP first, but not MCP only. AI agents are a primary design target. Every new capability ships with MCP tools. But the runtime SDK, web components, and Forge API are usable without MCP. Do not couple the platform to a single protocol, even if it is currently the most important one.
AD-07
Accessibility is not a feature. It is a constraint on every feature. Every PIS schema must include ARIA labels in all 12 supported languages. Every animation must respect prefers-reduced-motion. Every color mapping must pass WCAG AA contrast ratios. The runtime validates these automatically.
AD-08
No framework migration. Stay vanilla JS for core. The current vanilla JS + ES modules architecture works well for the npm packages and MCP server. Adding React/Vue/etc. would increase bundle size and maintenance burden. Framework wrappers are thin adapters that depend on the vanilla core.

Part VII

Risks & Mitigations

The top risks to the plan and how we handle them. Each risk has a mitigation that is actionable today, not a hope.

HIGH
AI generation quality is not good enough
LLMs may produce invalid PIS schemas, ugly icons, or semantically wrong outputs. Users try Forge once, get bad results, never return.
Mitigation: Phase 3 ships with a hybrid approach. The visual grammar engine handles 80% of cases with rule-based composition (deterministic, high quality). AI is used for the 20% novel cases. Rigorous post-generation validation catches errors before user sees them. If AI quality is insufficient at Phase 3 launch, ship with grammar engine + curated primitives first; AI is gated behind a quality threshold.
HIGH
No one adopts the parametric model
Developers are used to downloading SVG files. They may not see the value of a runtime or parametric schema. "Just give me the SVG."
Mitigation: Phase 1 (State Icons) proves value before the parametric model is visible. If state icons gain adoption, Phase 2's parametric model is "the same thing, but for any icon." If state icons fail, pivot to a simpler value prop (e.g., better SVG export from MCP) and defer the parametric vision.
MEDIUM
Bundle size kills runtime adoption
Frontend developers are extremely sensitive to bundle size. If @supericons/runtime is >20KB, many will reject it outright.
Mitigation: Hard budget: core runtime < 8KB gzipped. Tree-shaking is mandatory — every feature is an optional plugin. If performance targets are not met, cut features (e.g., defer Canvas renderer, simplify theme engine). Ship a bundle-size CI check that fails builds on regressions.
MEDIUM
Big players copy the approach
Figma, FontAwesome, or a well-funded startup ships a parametric icon system with better design tooling.
Mitigation: Speed to protocol standardization is the defense. The semantic search engine, 21K icon catalog, MCP integration, and 12-language i18n are existing moats. The registry network effect (if Phase 4 ships first) is the ultimate defense. Move fast on Phase 1–2 to build brand and community before anyone else ships parametric icons as a product.
MEDIUM
LLM API costs are unsustainable
Forge generation requires LLM calls. At scale, costs could exceed revenue from API pricing.
Mitigation: Phase 3 uses the grammar engine as primary path (zero marginal cost). LLM calls are reserved for novel compositions that the rule engine cannot handle. Cache generation results aggressively. Monitor cost-to-revenue ratio weekly. If costs exceed 30% of Forge revenue, raise prices or tighten free tier limits.
LOW
MCP standard changes break the server
The Model Context Protocol evolves, deprecating or changing the transport/API in ways that break @supericons/mcp.
Mitigation: The MCP server is a thin wrapper over the core runtime. If MCP changes, adapt the server. The runtime, state icons, and Forge API are MCP-agnostic. Additionally, the hosted HTTP transport provides a stable API surface regardless of MCP evolution.
