Supericons.

A manifesto for the visual vocabulary of the agentic era.

Icons have always been the externalization of human thought into visual form — from cave paintings to floppy disks to spinning rings. Chapter I — Origin

Icons have always been
human thought made visible.

Thirty thousand years ago, a human pressed pigment into a cave wall and drew a bison. That was the first icon. Not decoration — communication. A thought externalized into a form that another human could see and understand.

That impulse never stopped. Egyptian hieroglyphs began as drawings of things — a mouth, an eye, a bird — and slowly became symbols for sounds. The drawing abstracted into convention. The picture of a mouth stopped meaning "mouth" and started meaning something agreed upon by a community of users.

This is the first principle that all of icon history proves: icons do not have inherent meaning. They have agreed meaning. Proposed by someone. Adopted by the many. Eventually forgotten as a proposal and accepted as fact.

The floppy disk is no longer manufactured. It is still the universal symbol for save. The object died. The agreement survived.

Susan Kare designed the Mac's icons in 1984. Nobody voted on them. She proposed. Apple shipped. A billion users learned. The proposals became invisible — which is the highest form of design success. The meaning felt inevitable, not invented.

This is how visual conventions have always been set. A designer proposes. The masses adopt. The convention calcifies. Not democracy — authority. The authority of taste combined with distribution.

Now something unprecedented is happening. Software is being built not only by humans but by AI agents. Those agents need a visual vocabulary. Nobody has proposed one yet. The gap is open. The convention is unset. And whoever sets it carefully will define how the agentic era looks and feels to the humans who live in it.

Chapter II — The Problem with Icons Today

A drawing that knows
nothing about itself.

Today, an icon is an inert file. An SVG. A PNG. A glyph in a font. It carries a shape and a name. That is all. Everything else — what it means, when to use it, how it should move, what it communicates to a screen reader, whether it is appropriate for a high-risk context or a casual one — exists nowhere in the file. It lives in the designer's head, in a PDF style guide nobody reads, or not at all.

A typical icon today
A drawing. A shape. A name.
Silent about its own meaning.
Cannot be reasoned about.
No guidance on when to use it.
No accessibility metadata built in.
Static. Dead. A file.
Chosen by human hunt and instinct.
An agent guesses at best.
A supericon
A drawing that knows what it means.
Carries its own semantic profile.
Can be queried and reasoned about.
Defines when to use it and when not to.
Accessibility built into the structure.
Alive to context and state.
Chosen by intent, not instinct.
An agent executes correctly.

The problem is not that icons are poorly drawn. Most are fine. The problem is that visual meaning is locked in human heads and design documents — inaccessible to the systems that now build software.

An AI agent can generate a spinner. It can draw a checkmark. It has absorbed every icon ever published on the internet through its training. It has, in that sense, a minimum viable taste profile — the statistical average of human visual decisions, weighted by what got published and indexed.

The agent has pattern-based visual competence. It does not have contextual visual judgment. Those are very different things.

It cannot know that a pulsing spinner is wrong for an operation the agent is retrying after failure — because that state needs a different visual object with a different semantic meaning. It cannot know that a red pulsing icon at medium risk creates alarm where calm attention is what the user needs. It picks from patterns. It cannot reason from principles.

Chapter III — The Core Problem

The bottleneck is no longer
generation. It is judgment.

GPT Image 2.0 can generate a coherent set of fifty icons from a design reference file, without being told how to draw them. The visual grammar is recognizable. The stroke weights are consistent. The icons look like icons.

This proves something critical: visual generation is solved. Visual judgment is not.

Problem 01
Agents build without visual reasoning

An agent builds a UI correctly but visually wrong. The logic works. The icons communicate the wrong thing. The user is confused. The agent had no way to know better.

Problem 02
Meaning is not in the file

Every icon carries a shape. None carry their meaning, their context of use, their accessibility requirements, or their behavioral guidance. The meaning lives in human memory and gets lost in translation.

Problem 03
New concepts have no conventions

The agentic era has created visual concepts that did not exist before — ai-thinking, risk-high, pending-approval, agent-working. Nobody has defined what these look like. The gap is open and filling with noise.

Problem 04
Inconsistency compounds at scale

When agents build thousands of products, each making arbitrary visual decisions independently, the result is visual cacophony. Users cannot read the signals. Trust erodes. The promise of agentic software fails at the surface.

Problem 05
Accessibility is always an afterthought

ARIA labels, reduced-motion behavior, contrast requirements, screen reader descriptions — these are added manually if at all. There is no structure that makes them automatic.

Problem 06
Taste cannot be prompted

You can tell an agent to "use appropriate icons." You cannot prompt it into knowing what appropriate means for a high-risk financial transaction viewed by a user with vestibular disorders. Judgment cannot be improvised — it must be encoded.

Chapter IV — Definition

What is
a Supericon?

The definition

A Supericon is a programmatic visual object — shaped by human judgment, readable by AI agents — that carries its own meaning, context of use, motion behavior, and accessibility metadata, so that any system that needs to make a visual decision can make it correctly, consistently, and with taste it did not develop itself.

The key word is programmatic. A supericon is not a file you download. It is a structured object you query. It knows what it is, what it communicates, when it belongs, and when it does not. It can answer questions. It can be reasoned about. It participates in a system.

The second key word is human judgment. A supericon is not generated by an agent. It is shaped — proposed, reviewed, and approved — by a human with taste and authority. The agent executes. The human decides. The supericon is the vessel that carries the decision forward, into every product built by every agent that queries it.

01
A drawing
The visual form — animated SVG with static and reduced-motion variants. Beautiful, coherent, belonging to a visual family.
02
A semantic profile
Structured JSON that declares the meaning: state, risk level, confidence, urgency, reversibility, motion behavior. Machine-readable. Agent-queryable.
03
Behavioral guidance
Use-when. Avoid-when. Each avoid-when names the correct alternative. Not generic — specific. A profile that could apply to any icon is not done.
04
Accessibility built in
ARIA label, aria-live, role, reduced-motion behavior — present in the structure, not added later. Correct by default, not by effort.
05
Human authority
Every profile approved by a human with taste. The agent generates candidates. The human judges. The approved judgment propagates to every agent that queries the system.
A regular icon is a drawing. A supericon is a drawing that knows what it means — and can say so to a developer, an agent, an accessibility tool, or any system that needs to make a visual decision correctly.
Chapter V — For Whom

Supericons is built
for four users.

In order of strategic priority.

Primary — The AI Agent
Building UI without visual judgment

The agent can generate. It cannot judge. Supericons gives it a visual vocabulary it can reason about correctly — so the software it builds communicates meaning, not just shape. This user is new. No one has solved for it. It grows exponentially. This is the wedge.

Secondary — The Developer
Shipping faster with correct visuals

Today: search, download, resize, add hover states, write ARIA labels, argue about which icon to use. Tomorrow: describe intent, get the right icon with everything included. The developer stops thinking about icons and starts thinking about products.

Tertiary — The Designer
Scaling visual language, not individual icons

Design the visual system once. Define the meaning once. Watch it propagate into every product built by every agent that uses Supericons. Design the language, not the individual words. That is the work worth doing at scale.

Ultimate — The End User
Software that communicates clearly

They do not know what Supericons is. They notice that software feels clearer. Icons tell them when to wait, when to act, when something is dangerous. The visual language is legible in the way road signs are legible — consistent enough that recognition is instant.

The chain matters. Solve for the agent first — and the developer, designer, and end user benefit automatically. The agent is the leverage point. Every other user is downstream of it.

Chapter VI — How

The judgment loop that
makes it work.

The mechanism is simple. The execution is careful.

①
Human creates icons exist on the internet
Decades of human-designed icons — Lucide, Phosphor, Material, thousands of Dribbble shots — are the raw foundation. This collective human taste is the corpus agents were trained on. The baseline is already set by human history.
②
Agent generates candidates
Using that training, an agent produces visual candidates. It has pattern-based competence. It draws things that look like icons. This is generation without judgment — competent but context-blind.
③
Human judges and approves
A human with taste reviews the candidates. Does this look right? Does the motion communicate the state? Is the animation calm or alarming? Does it belong in this visual family? The human does not draw — the human decides. That is the authority.
④
Human writes the semantic profile
The judgment gets encoded. State, risk, confidence, use-when, avoid-when, accessibility metadata. This is the hardest part. A profile that passes review can tell any agent, in any context, exactly when this icon is correct and what alternatives exist when it is not.
⑤
Future agents query, not guess
Any agent building any product queries Supericons by intent. "Icon for: process running, high-stakes, user waiting, no action required." It gets back the right icon, the right code, the right ARIA label, and the reasoning. It executes with taste it did not develop. The human judgment propagates at scale.
⑥
Conventions form and evolve
As adoption grows, the Supericons definitions become the agreed conventions of the agentic era — like the floppy disk, but deliberately chosen, structured, and updatable. Unlike the floppy disk: the meaning can evolve when the world changes, because it is structured data, not a frozen image.
// An agent building a payment confirmation screen queries: search_supericons({ intent: "payment processing, user waiting", context: "high-stakes, irreversible, fintech", format: "react" }) // Returns: { icon: "loading-ring", reason: "Calm indeterminate wait. No user action needed.", aria_label: "Processing your payment", avoid: "Do not use error-critical — operation has not failed", snippet: "<LoadingRing label='Processing your payment' />" } // The agent did not guess. It reasoned. The human judgment was upstream.

Chapter VIII — The Manifesto

What we
believe.

I
Icons are not decorations. They are the externalization of human thought into visual form — and they have been since the first drawing on a cave wall.
II
Icons do not have inherent meaning. They have agreed meaning — proposed by someone with authority, adopted by the many, and eventually forgotten as a proposal.
III
The agentic era has created a gap. New visual concepts — ai-thinking, risk-high, pending-approval — have no established convention. Someone will fill that gap. It should be filled carefully.
IV
AI agents can generate visuals. What they cannot generate is visual judgment — the contextual knowledge of what is correct, what is wrong, and why it matters to the human experiencing it.
V
The bottleneck is no longer generation. It is judgment. And judgment must be encoded by humans — not improvised by agents at runtime.
VI
Humans are not removed from Supericons. They are concentrated into it. One person's carefully considered taste, encoded once, propagates through every agent that queries the system — into every product, experienced by every user.
VII
A Supericon is not a file. It is a declaration: this is what this visual object means, this is when it belongs, this is what it communicates to a human, and here is what to use instead when it does not fit.
VIII
Accessibility is not a feature. It is built into the structure — present by default, not added by effort. Visual meaning that cannot reach every human is incomplete meaning.
IX
We do not ship icons. We propose visual conventions for the agentic era — knowing that the conventions we set today will shape the visual experience of software for a generation.
X
Unlike the floppy disk — meaning encoded in Supericons can evolve without losing continuity. Because it is structured data, not a frozen image. That is the most important thing we do that no icon system before us could.

The principles that govern every build decision:

Build principle 01
Agent first, always

Every feature is evaluated through the question: does this make it easier for an agent to make a correct visual decision? If not, it is decoration.

Build principle 02
Profiles before pixels

The semantic profile is the product. The visual is the expression of it. A beautiful icon with a vague profile is a failure. An imperfect icon with a precise profile is shippable.

Build principle 03
Judgment is human, execution is agent

We do not automate taste. The agent generates candidates. The human approves. That division is permanent and intentional. The moment we skip the human review, we stop building Supericons and start building just another icon generator.

Build principle 04
Revenue is signal, not scale

A paying customer is evidence that the product solves a real problem. We treat early revenue as learning, not as a business. The business comes from doing the learning correctly.

Build principle 05
Accessibility is in the protocol

ARIA labels, reduced-motion behavior, contrast compliance — these are present in the structure from day one. Not added later. Not optional. A supericon without accessibility is not a supericon.

Build principle 06
Meaning can evolve

We set conventions deliberately, knowing we may need to revise them. The structure allows this. We track what we defined, when, and why — so future revision is principled, not arbitrary.
