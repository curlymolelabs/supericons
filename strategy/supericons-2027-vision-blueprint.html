Product Requirements

Pillar-by-Pillar PRD

What to build, why it matters, and exactly how to get there from current state.

01
Pillar 1

Governance Icon Collections

What to ship

  • Agent Lifecycle Pack (50 icons): idle, observing, planning, executing, waiting, blocked, uncertain, done, error plus variants
  • Trust and Authority Pack (50 icons): approved, suggested, auto-executed, confidence levels, delegation, override
  • Risk and Consequences Pack (40 icons): irreversible, external access, payment, PII detected, policy blocked
  • Disclosure Pack (30 icons): trace, audit log, hallucination-risk, reasoning chain, memory accessed

How to get there

  • Extend existing Agentic AI Kit (10 icons) as the foundation
  • Use existing premium collection workflow (start-premium-collection -> animated-icon-design -> finalize)
  • Run 5-second recognition tests on each icon
  • Validate with agent usability tests: can a coding agent pick the right icon from metadata alone?
// 9 core agent states per icon (outline + filled + animated) states: ["idle", "observing", "planning", "executing", "waiting", "blocked", "uncertain", "done", "error"]
02
Pillar 2

Stateful Animation Engine (Motion Lab v2)

What to ship

  • State-to-preset mapping layer on top of existing Motion Lab (no engine rewrite)
  • CSS custom property API: --si-state drives animation
  • New MCP tool: get_stateful_icon
  • State machine schema published per governance icon

How to get there

  • Map existing presets (pulse, spin, bounce, shake) to semantic states
  • Add CSS custom property API to each governance icon's CSS output
  • Extend MCP server with get_stateful_icon returning SVG + state CSS + a11y
  • Ship as Motion Lab v2, Pro tier
.si-state { --si-state: idle; /* changed by JS at runtime */ --si-color: currentColor; --si-intensity: 100; } /* CSS reacts to state change automatically — no JS dependency */
03
Pillar 3

MCP Semantic Protocol (v1.0)

4 new MCP tools

  • request_semantic_icon: intent-based resolution
  • get_stateful_icon: full state bundle
  • get_icon_grammar: composable components
  • list_governance_icons: taxonomy browser

Semantic request schema

  • intent: "indicate_agent_state"
  • state, context, risk_level, contrast_mode
  • Response: SVG + CSS + a11y + usage_html + risk_badge
  • Bumps server to v1.0, documented and versioned
// Before: agent guesses keyword search_icons({ query: "loading" }) // After: agent expresses intent request_semantic_icon({ intent: "indicate_agent_state", state: "executing", context: "payment_flow", risk_level: "high" })
04
Pillar 4

Dual-Surface Design System

Human surface

  • SVG in all size variants
  • CSS animation + state schema
  • a11y: role, aria_label, aria_live
  • Style variants: outline, filled, duotone

Machine surface

  • semantic_id: "governance.agent_lifecycle.planning"
  • purpose, state, synonyms[]
  • composable_with[], incompatible_with[]
  • recommended_context[], risk_level
1

Governance icons get full dual-surface metadata at design time. Start with all new packs.

2

Free icons backfilled using telemetry — zero-result searches tell us which icons to tag first.

3

Open-source the schema. Other icon libraries adopt it. Supericons becomes the standard-setter.

05
Pillar 5

Icon Grammar / Agent-Assembled Components

Grammar primitives

  • Base glyph: core icon
  • State ring: colored ring indicating agent state
  • Confidence badge: high / medium / low overlay
  • Authority marker: human / agent / system origin
  • Risk stripe: left-border color coding

Deliverable

  • Grammar specification document (open)
  • SVG compositor function (runs in MCP or browser)
  • MCP tool: get_icon_grammar
  • Returns: assembled_svg, assembled_css, components{}, a11y
get_icon_grammar({ base: "shield", state: "executing", confidence: "high", authority: "agent" }) // Returns: assembled SVG + CSS + a11y string // a11y: "Agent-initiated shield action, executing with high confidence"
06
Pillar 6 (Spec Phase Only)

Multimodal Signal System

2027 scope: spec + visual + LED

  • Publish multimodal signal spec as open standard
  • Visual + LED profiles for all governance icons
  • Free integration for early IoT/robotics partners
  • Haptic/audio/spatial: 2028+ opportunity

Signal profile schema

  • state + visual fields
  • led: pattern, color, frequency_hz
  • haptic: pattern, intensity
  • spatial: shape, color, pulsing

Adoption Strategy

How to Trigger the Spark

For agents, for humans, and for the ecosystem. Three parallel adoption vectors.

smart_toy For Agents

  • MCP is the distribution channel. Free tier must be generous enough every coding agent installs it
  • Semantic resolution is the hook: once an agent discovers intent-based requests it never goes back
  • List on Claude MCP directory, OpenAI plugin store, Cursor marketplace
  • Zero-result telemetry drives the build backlog: agents tell us what to build next

person For Humans

  • The Icons Future Vision page (already built) is the manifesto
  • Open-source the dual-surface schema: builds trust, invites contribution
  • Design system integration guides for Tailwind, Shadcn, Material
  • "State of Icons" annual report positions Supericons as the authority on agentic iconography

hub For the Ecosystem

  • Partner with AG-UI, Vercel AI SDK, LangChain: become the default icon provider
  • "Powered by Supericons" badge for apps using governance icons
  • Community governance icon proposals: developers submit, Supericons curates
  • Certified packs that include multimodal profiles for robotics/IoT partners

lock Moat Protection

  • First-mover on governance iconography: ship fast, establish the standard
  • MCP network effect: more agents = more telemetry = better recommendations
  • Semantic metadata is the lock-in: switching to a dumb SVG library is a downgrade
  • Open spec, closed implementation: schema is free, tagged corpus + engine is the product
