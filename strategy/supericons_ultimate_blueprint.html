// 04 — THE CURATION SYSTEM

From Icon Search Engine to Icon Decision Layer

Supericons began with a semantic search bar. That was the right first move for human discovery. The next evolution is fundamentally different: a decision layer that serves both humans and agents by converting icons from files into decisionable assets.

🧠
The central design insight: Humans and agents both have the same problem in different forms. Humans experience choice paralysis across 20K icons. Agents experience metadata poverty that prevents confident selection. Both are solved by the same thing: a rich, structured, opinionated semantic layer. Humans see it as "Collections." Agents see it as "Schema." One system, two interfaces.

The Five Core Score Families (From Research)

Craft Score
Legibility, geometry, stroke balance, distinctiveness
Intent Score
Semantic match, ambiguity risk, synonym coverage
Surface Score
Sidebar fit, toolbar fit, badge fit, hero fit
Coherence Score
Family similarity, density match, visual rhythm
Outcome Score
Accepted by human, retained, reused, agent success rate

New Object Types in the Product

🖼
1. Icon
With full manifest: semantic aliases, trust tier, affinity scores, co-occurrence partners, contraindications.
📦
2. Collection
Intent-based, pre-curated set answering "what icons do I need to build X?"
🔄
3. Workflow Pack
Icons for a complete user flow: onboarding, payment, AI chat, incident response.
🖥
4. Surface Kit
Icons for a specific UI surface: sidebar, command palette, auth settings, billing center.
📚
5. Source Family
A scored, trusted source with reliability tier, maintenance signal, and license clarity.
🤖
6. Agent Recipe
A complete prompt + MCP call sequence for an agent to build a full icon set for a feature area.

// 07 — THE TRI-CAMERAL JUDGMENT ENGINE

Who Decides What Is a Good Icon?

The deepest moat Supericons can build is not more icons. It is a defensible judgment graph built from three distinct intelligence sources. Human-only judgment does not scale. AI-only judgment is too brittle. Popularity-only collapses to the most familiar, not the most suitable.

👤
Tier 1: Human Taste Council
Experts, active builders, and high-signal users who shape the aesthetic and contextual truth. Humans are the only reliable judges of: symbolic appropriateness, emotional tone, cultural nuance, brand fit, product maturity, and whether something feels premium vs generic. They define the constitution.
Constitutional layer
🤖
Tier 2: Model Critic Layer
AI evaluates what can be made explicit: legibility at 16px, stroke consistency, silhouette distinctiveness, semantic closeness, collection coherence, duplication detection, ambiguity rate. AI is the structured critic and diagnostic layer, not the final taste judge.
Diagnostic layer
⚡
Tier 3: Agent Outcome Evidence
Agents vote through outcomes, not opinions. What icon did they select? Was it accepted or replaced by the human? Did it survive 7 days in the project? Did the bundle remain coherent? Agent evidence is the most honest signal because it is not self-reported.
Outcome evidence layer
🏆
The Judgment Graph: Instead of a "like" button, every vote is an evidence object that records: rater type, task context, surface, confidence, candidate alternatives, selected icon, rationale tags, and downstream outcome (retained/replaced/reused). This is a design intelligence system, not a social engagement metric. It creates earned reputation rather than influencer-style popularity.

Taste Staking: The Novel Mechanism

A voter can stake a contextual claim: "This icon will outperform the current default for enterprise billing sidebars." If later evidence supports the claim, reputation rises. If contradicted, calibration falls. This creates a market of taste and foresight, not a pile of anonymous likes. It rewards design maturity over raw activity.

// 08 — MCP API: AGENT-NATIVE TOOLING

Seven Agent Tools That No Icon Library Has

The current Supericons MCP exposes search_icons and get_icon. Seven additional tools unlock the complete agent-native curation architecture. An agent using these tools can select, justify, and complete an entire icon set for a feature area without any human visual review.

🎯
get_collection_for_intent
Agent asks: "What icons should I use to build X?" Returns a curated, pre-validated collection for a stated intent. Accepts design_system, trust_tier_min, and format as filters.
Primary agentic entrypoint
📋
get_icon_manifest
Returns the full structured manifest for one icon: semantic aliases, trust score, design affinity, co-occurrence partners, use cases, contraindications. Validate before committing to a selection.
Pre-selection validation
🔗
recommend_co_occurring
Given one icon already chosen, returns the strongly co-occurring icons that appear alongside it in production apps. Completes an icon set from a single anchor selection.
Set completion
📊
score_icon_candidates
Given a list of candidate icons and a context, score them on all five score families: craft, intent, surface, coherence, outcome. Returns a ranked, reasoned shortlist.
Comparative ranking
🏛
list_reliable_sources_for_domain
Returns ranked source families for a given domain (ai-ml, ecommerce, devtools, security) with trust tier, license, and domain fit scores. Helps agents pick the right library, not just the right icon.
Source intelligence
🔍
explain_icon_choice
Returns a human-readable and structured rationale for why a given icon was chosen for a given context. Enables agents to explain their own decisions to human reviewers.
Auditability
🔄
swap_to_more_coherent_family
Given a mixed-family icon set that has style inconsistencies, recommends a replacement set from a single coherent family. Enforces visual system cohesion programmatically.
Coherence enforcement
