Executive Decision

Decision: Remove the `Jobs` sidebar as a primary nav concept. Keep taxonomy and telemetry. Re-express use case as a chip/filter axis above the grid.

The current taxonomy model is good. The current browse IA is not. Purpose should refine search and library browsing, not compete with them as a parallel top-level navigation branch.

Copy guidance: use Purpose on the site chip row, keep job_category internal only, and use Purpose / Top Purposes in product UI.

Target UX Model

Site UI

Search + Facets

Search remains the primary entry point. Libraries remain in the sidebar. Use-case chips sit above the grid and combine with libraries.

Distribution

GitHub Kits

Curated free kits live as separate distribution assets and repos. They should not shape the site browse IA directly.

Intelligence Layer

Taxonomy + Evidence

icon_metadata, icon_evidence, icon_scores, synonyms, and curated aliases stay underneath both human and agent experiences.

Implementation Phases

Phase 1: IA Refactor

Remove the sidebar `Jobs` section, add a `Purpose` chip row, and split browse state into activeLibrary and activeJobCategoryFilter.

Phase 2: Search Enhancement

Extend public/synonyms.json and mcp/public/synonyms.json with missing Kit 01 AI-domain terms like quota, tool call, and guardrail.

Phase 3: Curated Precision Layer

Add lib/icon-semantic-aliases.js as a lightweight alias map for the 150 seeded icons so curated search can rank intended concepts ahead of noisy substring matches across both the site and MCP.

Phase 4: Evidence-Led Iteration

First complete an admin language pass (`Top Purposes`, human labels, blank-value note), then use icon_evidence and icon_scores to prioritize future semantic coverage instead of tagging the entire corpus upfront.

Interaction Rules

  • Clicking the All purpose chip clears only the purpose filter.
  • If the user is on Lucide + AI & Agents and clicks All, the state becomes Lucide + All Purposes.
  • If no specific library is selected, choosing a purpose chip filters across all libraries.
  • Changing the purpose chip does not clear the active search query.
Implementation note: keep activeLibrary and activeJobCategoryFilter as separate state values, then combine them with AND semantics inside applyFilters().

Acceptance Criteria

  • Use-case chips render above the grid.
  • Library AND Purpose filtering works correctly.
  • New copy/favorite events still record job_category.

  • Admin explains blank purpose values when icons fall outside the seeded taxonomy.
  • Synonym updates improve AI-domain retrieval in both site and MCP contexts.

Risks and Mitigations

  • Chip row clutter: start with the three seeded categories and scale later.
  • Over-broad synonyms: keep broad terms in synonyms and precision in curated aliases.
  • Taxonomy feeling hidden: make the chip row visually clear and keep labels explicit.
  • Refactor churn: preserve the data model and telemetry; change only presentation and browse state.

Final Recommendation

Best approach: keep the taxonomy, remove the Jobs sidebar, add purpose chips, improve AI-domain search, add curated aliases for the 150 seeded icons, and let evidence guide what expands next.

This keeps the strongest part of the current work, corrects the weakest part, and aligns Supericons with its real thesis: a semantic icon intelligence system for humans and agents, with GitHub kits as a separate distribution channel.
