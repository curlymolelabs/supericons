From Icon Library to Visual Protocol

AI can build any icon, animation, or component. The code is not the moat. The standard is the product. This plan turns that insight into a concrete, buildable sequence where every step generates revenue or adoption.

Core Insight

The Standard Is the Product. The Decisions Are the Moat.

savings Token Economics

Building custom AI-state icons from scratch burns expensive AI tokens. Pre-built packs save hours of prompt-and-iterate cycles.

palette Design Consistency

Designing 40 icons that look like a family requires human taste. AI generates unique icons every time. That is art, not a system.

timer Time Savings

Pre-built, tested, animated components save hours of work over prompting AI to build them from scratch.

hub Network Recognition

As the standard grows, using it means your UI is recognizable across apps. Users learn the visual language once.

Strategy

Two Tracks Running in Parallel

Track A: Cash Flow (Keep Running)

The existing business. Premium animated packs, MCP server, search engine. This pays for everything else. Keep shipping, keep improving, keep growing MCP adoption.

Track B: Visual Protocol (Build Progressively)

The new vision. Governance icon packs with si:icon metadata baked in. Each step is independently valuable and generates revenue. No step requires the previous one to be "complete."

Track B: The 8 Steps

Build in Order. Each Step Generates Value.

Every step ships a product, generates revenue or adoption, and plants a seed for the standard.

1

Design the Agent Lifecycle Icons

9 static SVGs for AI agent states that do not exist in any icon library. Every AI app that runs agents needs to show these states. Today they use spinners, text, or nothing.

  • Agent idle, planning, executing
  • Waiting for approval, blocked
  • Completed, failed
  • Monitoring, learning
Revenue: $29-49 pack
2

Add si:icon Metadata

Embed the si:icon XML namespace into each of the 9 icons. This costs almost nothing to add (just XML tags) but it is the first real artifact of the si:// standard. Every icon sold with metadata is a seed planted.

Standard: si:icon namespace
3

Add request_semantic_icon to MCP

One new tool in the MCP server that accepts intent instead of keywords. Agents describe what they need ("waiting for approval in payment flow") and get the right icon. Initially resolves only against the Agent Lifecycle pack.

MCP: intent-based resolution
4

Ship Trust/Authority + Risk Icons

14 more icons across two collections. Trust and Authority (8 icons): human-initiated, agent-initiated, confidence levels, verified, audit trail, override. Risk and Consequences (6 icons): irreversible, high-risk, cost, data exposure, rate limit, cascading.

Revenue: $29-49 each or $99 bundle
5

Build Grammar Primitives

Define the composable building blocks: state ring (colored ring for current state), confidence badge, authority marker, risk stripe. These let icons express compound states like "risky agent action with medium confidence."

Standard: composition rules
6

Publish the si:// Spec

Publish the namespace schema, URI format, grammar rules, state machine definitions, and semantic event names as a formal open specification. When a developer prompts "follow the Supericons standard," this is what they reference.

Standard: published spec
7

Build the <si-icon> Web Component

A single Web Component that renders any Supericons icon with full state management, accessibility, semantic events, and grammar composition. One tag, state-driven, programmable.

Revenue: @supericons/components npm package
8

Pro MCP Tier

Split MCP into free (20K icons, keyword search) and pro ($12/mo: intent resolution, stateful animations, grammar compositor, governance packs). The MCP server is the primary distribution channel.

Revenue: $12/mo recurring

Risk Register

Honest Risks and Mitigation

Nobody buys the Agent Lifecycle pack

The market is early. If 50 sales in 3 months fails, pivot icons to broader "status/state" icons for any dashboard, not just AI apps.

Frameworks absorb Trust UX

Vercel or shadcn could add basic agent status. Mitigation: go deeper than frameworks will. 9 states, 5 primitives, 4 collections. Frameworks build 3-state. We build the full vocabulary.

AI generation makes pre-built icons irrelevant

Medium-term risk (2-3 years). Mitigation: the standard is the product. If AI generates icons "following the Supericons standard," we win. Revenue shifts from selling icons to selling ecosystem.

The market is too early

Most developers are still building basic AI apps. Mitigation: Track A sustains the business while Track B waits for market timing. We pre-position in a small market that will grow.

The Kill Metric

50 sales of the Agent Lifecycle Pack in 3 months.

If that happens: the niche is real, keep building. If not: pivot the collections to broader dashboard icons and revisit governance positioning in 6 months.

The honest summary: Supericons is pre-positioning in a tiny market that every trend says will become massive. Today, we sell premium icon packs to the small number of developers building agent apps. Tomorrow, when every SaaS product has an agent, we own the visual standard they all use. The risk is timing. The mitigation is cash flow from the icon search engine.
