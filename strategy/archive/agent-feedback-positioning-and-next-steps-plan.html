What We Learned From Agent Feedback (and What To Do About It)

An AI agent built our blueprint page and told us exactly how it chose icons. This document turns those lessons into clearer messaging, smarter design choices, and a sharper build order for the Supericons 2027 vision.

The Big Takeaway

Our Vision Is Right. Our Build Order Needs To Change.

The key insight: AI agents do not browse icons the way people do. They pick whichever icon library is easiest to use. They type icon names they already know from memory. They never actually "see" the icons they choose.

This means Supericons should not try to win by being a "prettier icon library." Instead, we should win by being the icon system that understands what you need. When an agent says "I need a trust icon for a payment screen," Supericons should be the only library that can answer that correctly. The big picture stays the same. The order we build things in is what changes.

What Changes

Four Things We Now Know

1. "Describe what you need" beats "guess the icon name"

Google Material Icons wins today because AI agents already have its icon names memorized. Supericons wins when the agent can simply describe what it needs ("a warning icon for a risky action") and get the right answer, no name-guessing required.

2. The icons that do not exist yet are our biggest opportunity

The agent struggled most with: confidence levels, who started an action (human or AI?), "waiting for your approval," audit trails, and memory access. These icons do not exist in any library. That is our premium product opportunity.

3. Agents need icon building blocks, not just single icons

The agent did not just need one icon at a time. It needed to combine pieces: an icon + a colored status ring + a confidence indicator + a label showing who triggered it. We need to build mix-and-match building blocks, not just standalone icons.

4. If we are harder to use than a simple link tag, agents will use something else

A Google font link takes one line. If Supericons takes more setup than that, AI agents will skip us. Making it effortless to start using Supericons is not just a nice-to-have. It is a requirement.

How We Should Talk About Supericons

Two Messages for Two Audiences

For people (designers and developers)

Supericons is the fastest way for modern builders to ship sharper interfaces with curated icons, animated packs, and ready-to-use exports.

For AI agents (coding assistants)

Supericons is the icon system that understands context. Describe what you are building, and get back the right icon with animation, accessibility info, and usage instructions.

What makes us different

Not "more icons." We offer: icons for AI concepts that nobody else has, the ability to describe what you need instead of guessing names, mix-and-match building blocks, animated state indicators, and delivery designed for both humans and AI.

The winner will not be the library with the prettiest static icons. It will be the system that makes it easiest for both people and AI agents to pick the right visual for the right situation.
Design Rules

How We Should Design Every New Icon Going Forward

Make icons easy to find by meaning, not just name

  • Tag every icon with its purpose (what is it for?)
  • Add keywords an agent might search for
  • Note where the icon works best (dashboard, sidebar, notification)
  • Note where the icon should not be used

Build the icons nobody else has

  • Who did this: human or AI? (authority)
  • How sure is the AI? (confidence)
  • "Your approval is needed" (human approval)
  • "This action is logged" (audit trail)
  • "The AI accessed its memory" (trace)

Build small pieces first, not a giant system

  • A small "confidence level" badge
  • A small "who triggered this" marker
  • A colored ring showing current state
  • A left-edge stripe showing risk level

Write docs that AI agents can use

  • Show: "How to ask for this icon"
  • List: "What search terms will find it"
  • Explain: "When NOT to use this icon"
  • Suggest: "Better alternatives for X"
What To Build and When

The Build Plan (In Order)

Step A

Remove friction and tag our best icons

  • Make sure our MCP package installs perfectly with one command, no errors
  • Write a guide: "How to ask for icons" (a phrasebook for AI agents)
  • Add meaning tags (purpose, use case, related keywords) to our top 100-200 most popular icons
  • Use our search data to figure out which "missing" icons people and agents are looking for most
We know it is working when: the MCP installs cleanly from the docs, the phrasebook exists, our best icons have meaning tags, and we have a prioritized list of which new icons to create next based on real search data.
Step B

Build the first set of "AI era" icons

  • Ship the Agent Lifecycle collection first (the 9 core AI states: idle, planning, executing, waiting, blocked, etc.)
  • Design the first building blocks: "who triggered this" marker, "confidence level" badge, "current state" ring, "waiting for you" indicator
  • Package our best free icon sets as proper, ready-to-install kits on GitHub
  • Every kit gets: a clear README, preview images, usage examples, and framework snippets
We know it is working when: the first AI-specific icon collection is live and clearly unique (no other library has these), and our GitHub kits look professional and are easy to install.
Step C

Let agents describe what they need (instead of guessing names)

  • Build the "describe what you need" tool: agents say "I need a trust icon for a payment flow" and get the right one back
  • Publish a browsable catalog of all our AI-era icons, organized by purpose
  • Expand meaning tags to cover all AI-era icons and our top free icons
  • When returning an icon, include a note explaining "why this icon was chosen" so agents (and developers) can learn
We know it is working when: an agent can describe a need in plain English and get a usable icon back in one call, and the results are better than guessing a keyword on Google Material Icons.
Step D

Icons that move with meaning and mix-and-match parts

  • Build a tool that returns icons with built-in animations: "planning" icons gently pulse, "executing" icons spin, "blocked" icons shake
  • Build a tool that assembles building blocks: agents request "shield icon + executing state + high confidence + agent initiated" and get a complete, ready-to-use visual
  • Connect our Motion Lab animation presets to icon states (so "pulse" automatically means "thinking")
  • Deliver complete bundles: the icon SVG + the CSS animation + the state rules + accessibility labels, all in one response
We know it is working when: Supericons starts behaving like a visual language system (mix and match parts to say anything), not just a catalog of static pictures.
Important messaging rule: Do not market the 2027 vision as if it already exists today. Be honest about what is live now, while clearly signaling where we are heading. Promise a direction, not a finished product.
