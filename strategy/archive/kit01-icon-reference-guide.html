Icon Reference Guide

Curation reference with semantic search mapping. Each card shows what to search in Supericons today, plus the AI-domain vocabulary that should return this icon — the semantic gap we close through icon_metadata and manifest-lite.json.

Lucide — 14 icons
Heroicons — 8 icons
Phosphor — 5 icons
Tabler — 4 icons
cpuGreen = works in Supericons search today
inferenceAmber = semantic gap — what devs type but get wrong or zero results. These become semantic_aliases[] in manifest-lite.json.
Rule: One icon per AI concept. One concept per icon. Every usage-map.md entry must answer: "Why this icon and not the obvious alternative?" The semantic aliases become the intelligence layer that routes developer intent to the right icon via MCP.

Looks likeTwo arrows crossing — like the shuffle button on a music player.

Selection Strategy
1.
Identify the AI concept you need (RAG retrieval, agent handoff, observability, etc.).
2.
Find the candidate icon. Use the green "Find by searching" terms to locate it in Supericons.
3.
Ask: does the visual shape match the concept without explanation?
4.
Check for conflicts: is this icon already assigned to a different concept in the kit?
5.
Write the usage-map.md entry with the "chosen over X because Y" rationale.
6.
Carry the amber semantic aliases into manifest-lite.json as semantic_aliases[] — this is what makes the MCP tool smart enough to return lucide:cpu when an agent asks for "inference compute quota".
usage-map.md Entry Format
## icon-name (library:icon-name) **Concept:** [one-line AI concept label] **Use for:** [2-4 bullet points of specific UI surfaces] **Not for:** [1-2 bullet points of contraindications] **Chosen over:** [alternative icon] because [1 sentence rationale] **Pairs with:** [2-3 icons commonly used in the same UI surface] **Semantic aliases:** [comma-separated list of amber tags from this guide]
RAG pipeline — the three-icon sequence:  Retrieve = lucide:shuffle  →  Augment = lucide:git-merge  →  Generate = lucide:sparkles. Three visually distinct stages, immediately readable to any AI developer without a legend.
