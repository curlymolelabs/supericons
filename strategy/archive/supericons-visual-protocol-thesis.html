The Visual Protocol for Human-AI Interaction

Supericons is building a system where every icon is a meaningful, self-describing, composable object that AI agents can understand and humans can trust. Not a search engine. Not a static library. A visual language.

Mission: Define what AI looks like when it talks to humans.
The Dream

Bigger Than a Library

Ordinary icon libraries are like a box of road signs dumped in a warehouse. Supericons wants to become: the road signs, the rulebook for what each sign means, the grammar for combining signs, and the traffic system that tells everyone how to read them.

mood Emoji for the Agent Era

Emojis gave humans a shared visual language for emotion. Supericons gives humans and AI agents a shared visual language for state, trust, and authority.

traffic Traffic Signals for Human-AI Trust

Traffic signals let strangers safely navigate shared roads without speaking. Supericons lets humans safely navigate agent behavior without reading logs.

translate A Language, Not a Warehouse

Languages have vocabulary (icons), grammar (composition rules), and intent (meaning). Supericons is building all three.

smart_toy Each Icon is a Tiny Agent

It carries its own identity, knows its own rules, can verify itself, introduces itself to any AI, and composes with other icons to say complex things.

Layer 2: Meaning

Icons That Describe Themselves

Every Supericons SVG carries a "passport" of metadata inside the file. The icon IS the documentation. Copy it anywhere and the meaning goes with it.

agent-planning.svg
<svg xmlns:si="https://supericons.dev/ns/v1"> <!-- What humans see --> <title>Planning</title> <!-- What AI reads --> <si:icon id="agent-planning" collection="agent-lifecycle"> <si:purpose>Show that an AI is currently planning</si:purpose> <si:tags>thinking, strategizing, preparing</si:tags> <si:use-when>The agent is planning before executing</si:use-when> <si:dont-use-when>The agent is idle or already done</si:dont-use-when> <si:pairs-with>confidence-badge, authority-marker</si:pairs-with> </si:icon> <path d="M12 2C6.48..."/> </svg>

Layer 4: Protocol

Describe What You Need, Get the Right Icon

The single biggest unlock for agent adoption. Agents describe intent in plain language. Supericons returns the exact right visual.

intent-based resolution
request_semantic_icon({ intent: "represent_governance_concept", concept: "waiting_for_human_approval", context: "payment_flow", state: "blocked" }) // Returns: exact SVG + CSS animation + a11y metadata // No name-guessing. No keyword-matching. Just the right icon.

This eliminates Google Material Symbols' biggest advantage: agents no longer need to know icon names from training data. They describe the need and get the answer.

Level 3: Dynamic (state-driven)

One HTML tag, many appearances. The icon receives a semantic state and automatically updates everything: color, animation, badge, and accessibility label.

state-driven icon
<!-- One tag. State-driven. Everything updates automatically. --> <si-icon name="agent-status" state="executing" confidence="high"></si-icon> // When state="executing": Animation -> spin, Ring -> green, Badge -> high, a11y -> "Agent executing" // Change to state="blocked": Animation -> pulse, Ring -> red, a11y -> "Agent blocked", Risk stripe appears // All from changing one attribute. The icon knows what to do.

Level 5: Programmable (component with API)

An icon with a full API. It accepts properties, manages internal state transitions, emits semantic events, and can be controlled by agents or frameworks.

programmable trust widget
const icon = document.querySelector('si-icon[name="payment-risk"]'); // React to live data icon.setState('high-risk'); icon.setConfidence(0.72); icon.setAuthority('agent'); // Listen for user decisions icon.addEventListener('si:approve', () => processPayment()); icon.addEventListener('si:override', () => openManualReview()); icon.addEventListener('si:explain', () => showReasoningChain()); // Query icon state icon.getState(); // "high-risk" icon.getConfidence(); // 0.72 icon.getMeta(); // { id, collection, purpose, tags, ... }

AI Generation Resilience

Why Advancing LLMs Make Supericons More Relevant, Not Less

If LLMs advance to create visually stunning icons on demand, does Supericons become irrelevant? The short answer: if Supericons stays a library, AI kills it. If it becomes the protocol, AI amplifies it.

What AI generation threatens

Drawing a single icon

LLMs will draw shields, locks, and gears well within 1-2 years. Any static SVG becomes commoditized.

Generating on demand

A pretty, unique icon generated in 200ms. Why download a pre-made one?

What AI generation CANNOT replace

Consistency across a system

AI generates a unique icon every time. Great for art, terrible for a design system. 40 independently generated icons look like strangers, not a family. Supericons is a curated, consistent system.

The protocol is not the pixels

What does "agent-planning" mean? What grammar rules govern composition? What state machine drives transitions? What events does the icon emit? AI draws pictures. Supericons defines the brain.

Vocabulary is product thinking

No LLM will decide the AI ecosystem needs 9 agent lifecycle states, 8 trust indicators, 6 risk visuals. That is product design: the decision of WHAT should exist, not HOW to draw it.

Standards outlast tools

HTTP outlasted every browser. JSON outlasted every database. If si:// becomes how agents think about icons, who draws the pixels is irrelevant.

The twist: AI generation as an OPPORTUNITY

AI generation does not kill Supericons. It could become the rendering engine UNDER Supericons:

The future model

1. Agent needs "waiting for human approval in a payment flow" → 2. Queries si:// protocol for the canonical concept, metadata, grammar, state machine → 3. Supericons returns the semantic definition → 4. AI generation renders it in the user's exact visual style (rounded, flat, 3D, whatever)

Supericons = the brain (meaning, grammar, protocol, state machines, events). AI = the hand (renders in any visual style on demand).

Static icons: an image file. AI generation replaces this. Supericons at full vision: a programmable trust widget that speaks both human and machine. AI generation cannot replace this. At best, it becomes a rendering engine underneath it.
Progressive Roadmap

Build in Order. Each Phase Generates Value.

No timelines. Just the right sequence. Each phase is independently valuable and funds the next.

Phase 1

Remove Friction, Build the Foundation

  • MCP installs perfectly with one command
  • Agent phrasebook: "how to describe icons to agents"
  • Meaning tags on the top 200 icons
  • Search telemetry driving the governance vocabulary backlog
  • Best free icon sets packaged as professional GitHub kits
Signal: MCP installs clean. Phrasebook exists. Search data drives priorities.
Phase 2

Ship the Icons Nobody Else Has

  • Agent Lifecycle Collection (first governance pack)
  • First grammar primitives: authority marker, confidence badge, state ring
  • Trust and Authority Collection
  • Every pack: README, preview, usage examples, framework snippets
Signal: Governance collections are live, unique, and generating revenue.
Phase 3

Icons That Describe Themselves

  • Define si:icon namespace schema (the passport format)
  • Export pipeline: every icon ships with embedded metadata
  • Tiny reader library (@supericons/reader, under 2KB)
  • Compact si:// URI format for lightweight embedding
  • MCP server self-indexes from its own SVG files
Signal: Copy any Supericons SVG into any project. The meaning goes with it.
Phase 4

Agents Describe What They Need

  • request_semantic_icon MCP tool (intent-based resolution)
  • Browsable governance taxonomy (list_governance_icons)
  • Meaning tags on all governance icons + top 500 free icons
  • "Why this icon was chosen" explanations in MCP responses
Signal: Agent says "trust icon for payment flow." Gets the right icon in one call.
Phase 5

Icons That Move With Meaning

  • CSS custom property API: --si-state drives animation
  • Motion Lab presets mapped to semantic states
  • get_stateful_icon MCP tool: SVG + state CSS + a11y in one call
  • Risk and Consequences Collection
Signal: Request "planning icon in blocked state." Get back a complete animated component.
Phase 6

Mix-and-Match Visual Grammar

  • Grammar specification: composition rules, positioning, sizing
  • SVG compositor engine
  • get_icon_grammar MCP tool
  • Disclosure Collection
  • Complete bundles: SVG + CSS + state + a11y, assembled
Signal: "Shield + executing + high confidence + agent initiated" returns a ready-to-use visual.
Phase 7

Verification and Trust

  • Content hashing (SHA-256) on all icon metadata
  • Digital signatures (Ed25519) for provenance
  • Public registry API at supericons.dev/registry
  • Open namespace schema published as industry standard
  • Evaluate blockchain for multi-vendor governance
Signal: Any tool can verify a Supericons icon is authentic and unmodified.
Phase 8

Ecosystem and Standard

  • Ecosystem tools: reader, CI linter, VS Code extension
  • "Powered by Supericons" badge program
  • Community governance icon proposals
  • Annual "State of Icons" telemetry report
  • Framework integrations: Vercel AI SDK, AG-UI, LangChain
Signal: Other projects reference the si:icon standard. The vocabulary is expected, not novel.
